Melhores modelos de NER: spaCy, GLiNER, Transformers e LLMs

O reconhecimento de entidades nomeadas (NER) encontra e classifica segmentos de texto, como pessoas, empresas e códigos de produto. Um sistema de produção também tem de normalizar esses segmentos, validar o resultado, cumprir um orçamento de latência e encaminhar os resultados incertos para revisão. Por isso, o melhor modelo depende прежде de tudo da estabilidade das suas etiquetas.

Use spaCy para etiquetas estáveis e pipelines rápidos. Escolha GLiNER quando as etiquetas mudam frequentemente ou faça fine-tuning de um classificador de tokens baseado em Transformer quando tiver exemplos anotados. Use extração estruturada baseada em LLM quando precisar de um registo complexo, em vez de uma simples lista de segmentos.

Como escolher

Comece pelo schema das entidades, não pelo modelo.

Se as etiquetas forem estáveis e existirem exemplos, treine ou faça fine-tuning de um classificador de tokens. É mais fácil de avaliar, mais barato de executar e mais previsível do que uma cadeia de extração com LLM.

Se as etiquetas mudarem semanalmente, use GLiNER ou um extrator com LLM enquanto a ontologia estabiliza. O objetivo é perceber qual deve ser o schema antes de investir orçamento em anotação.

Se o resultado for um registo estruturado, em vez de segmentos, use um LLM com structured outputs ou um pipeline híbrido. Muitas tarefas de extração empresarial não são NER puro. «Encontrar as partes, as obrigações, a data de entrada em vigor, a cláusula de cessação e a lei aplicável» é compreensão documental com campos de entidades.

Padrão de produção

Um sistema NER de produção tem normalmente três níveis:

  1. Extração de candidatos: spaCy, GLiNER, modelo Transformer, LLM, regras ou uma combinação destes.
  2. Normalização: mapear segmentos para IDs canónicos, códigos de produto, utilizadores, empresas ou entradas de uma ontologia.
  3. Validação: rejeitar etiquetas impossíveis, impor restrições do schema, eliminar segmentos duplicados e encaminhar os casos com baixa confiança para revisão.

A normalização transforma o texto extraído em dados úteis para o produto. Encontrar o segmento «Apple» é apenas o primeiro passo. O sistema ainda tem de determinar se significa a empresa, a fruta, uma família de produtos ou um ticker bolsista e, em seguida, mapeá-lo para um ID estável.

  • F1 de segmentos exatos
  • F1 de segmentos relaxados

  • tratamento de entidades aninhadas
  • precisão da normalização de entidades
  • falsos positivos por etiqueta
  • calibração da confiança
  • latência e custo por documento
  • taxa de correções humanas

Ficheiros de arranque do Zsh: .zprofile vs .zshrc no macOS e no Linux

Viacheslav Dubrov

2025-05-07 · Atualizado 2026-07-15 · 5 min · Ferramentas de desenvolvimento

Tradução automática Este artigo foi traduzido automaticamente a partir da versão original em inglês.

Se o terminal parece lento, ou se uma variável de ambiente aparece num terminal mas não noutro, a causa é frequentemente o modo de arranque do Zsh. Os dois ficheiros a que a maioria das pessoas recorre são ~/.zprofile e ~/.zshrc, mas nenhum dos nomes, por si só, indica se uma linha deve estar aí.

O Zsh escolhe os ficheiros de arranque com base em duas propriedades independentes: se a shell é uma login shell e se é interativa. As aplicações de terminal no macOS e no Linux podem escolher combinações diferentes, por isso deve inspecionar a shell em execução em vez de assumir que o sistema operativo decide por si.

Em resumo. Coloque a inicialização da sessão de login em .zprofile e o comportamento interativo em .zshrc. Mantenha .zshenv silencioso e minimalista. Não mova hooks interativos de gestores de versões para .zprofile nem carregue o perfil inteiro a partir de .zshrc; inspecione o código gerado pela ferramenta e siga as instruções atuais para Zsh.

O Zsh avalia duas flags independentes

Uma shell pode ser:

  • de login e interativa, como acontece normalmente quando o Apple Terminal inicia a login shell predefinida da conta
  • não-login e interativa, como acontece com uma zsh aninhada ou com muitas configurações de terminais no Linux
  • de login e não interativa, como acontece com zsh -lc 'command'
  • não-login e não interativa, como acontece com zsh -c 'command'

As aplicações de terminal, IDEs, sessões remotas, multiplexers e flags explícitas da shell podem escolher modos diferentes, pelo que o sistema operativo, por si só, não determina o resultado.

Pergunte à shell em execução em vez de adivinhar:

print -r -- "interactive=$options[interactive] login=$options[login]"

A ordem efetiva de arranque

O Zsh lê os ficheiros globais e, em seguida, o ficheiro de utilizador correspondente. Com as opções RCS predefinidas, a ordem dos ficheiros de utilizador é:

  1. $ZDOTDIR/.zshenv em todas as invocações do Zsh
  2. $ZDOTDIR/.zprofile se a shell for uma login shell
  3. $ZDOTDIR/.zshrc se a shell for interativa
  4. $ZDOTDIR/.zlogin se a shell for uma login shell
  5. $ZDOTDIR/.zlogout quando uma login shell termina normalmente

Se ZDOTDIR não estiver definida, o Zsh utiliza $HOME. As localizações dos ficheiros a nível do sistema dependem da instalação; as predefinições comuns são /etc/zshenv, /etc/zprofile, /etc/zshrc, /etc/zlogin e /etc/zlogout.

.zprofile é executado uma vez por processo de login shell, e não uma vez por início de sessão no computador. Se cada novo separador do terminal iniciar uma login shell, todos os separadores leem esse ficheiro.

Mantenha .zshenv aborrecido

Todas as zsh -c não interativas leem .zshenv. Um echo, uma chamada a um gestor de pacotes ou um subprocesso dispendioso nesse ficheiro pode corromper o output dos comandos e tornar os scripts mais lentos. A maioria dos utilizadores precisa de pouco ou nada neste ficheiro.

Uma variável exportada em .zprofile é herdada pelos processos descendentes dessa login shell. Não é automaticamente injetada em aplicações GUI, serviços ou shells não relacionadas cujo processo-pai nunca tenha lido o ficheiro.

Utilize .zprofile para configuração exclusiva de login

Um perfil pequeno pode definir predefinições exportadas e um path idempotente:

# ~/.zprofile
export EDITOR=nvim
export VISUAL=nvim

# Zsh ties the path array to the PATH scalar.
typeset -U path PATH
path=("$HOME/.local/bin" $path)
export PATH

typeset -U remove entradas duplicadas de arrays. Torna o carregamento repetido mais seguro, embora os ficheiros de arranque devam continuar a evitar trabalho desnecessário.

Utilize .zshrc para o estado interativo

# ~/.zshrc
setopt auto_cd hist_ignore_all_dups share_history

autoload -Uz compinit
compinit

alias ll='ls -lah'
bindkey -e

Aliases, widgets de completion, mapas de teclas, prompts e hooks de alteração de diretório pertencem à shell interativa que os utiliza.

Os gestores de versões atravessam a fronteira simples entre ficheiros

A recomendação «coloque os gestores de versões em .zprofile porque são lentos» não é fiável. Um gestor de versões pode emitir vários tipos de código:

  • um path ou uma variável de root estáticos
  • um path para command shims necessário aos processos descendentes
  • definições de completion
  • funções da shell que alteram a shell atual
  • hooks de alteração de diretório para mudança automática de versões

As partes interativas têm de existir em todas as shells interativas, incluindo uma zsh iniciada a partir de um editor. Por isso, a documentação atual do fnm coloca este hook em .zshrc:

eval "$(fnm env --use-on-cd --shell zsh)"

A documentação atual do pyenv também coloca a inicialização interativa completa em .zshrc:

export PYENV_ROOT="$HOME/.pyenv"
[[ -d $PYENV_ROOT/bin ]] && path=("$PYENV_ROOT/bin" $path)
eval "$(pyenv init - zsh)"

O pyenv documenta um modo pyenv init --path mais restrito para configurar o shim-path, mas o pyenv init completo também instala completion e funções da shell. Inspecione a documentação atual e o output gerado pela ferramenta antes de os separar.

Se o arranque for lento, meça-o antes de mover código para um modo em que deixe de funcionar.

Não carregue o perfil inteiro a partir de .zshrc

Uma solução comum para compatibilidade entre plataformas é:

# Avoid this blanket coupling.
source ~/.zprofile

Isto transforma ações exclusivas de login em ações executadas por cada shell interativa e pode repetir o arranque de agentes, o acesso ao keychain, o output ou alterações ao path.

Se as shells interativas de login e as que não são de login precisarem de um pequeno conjunto de exports estáticos, extraia um fragmento idempotente e carregue-o deliberadamente:

# ~/.config/zsh/environment.zsh
typeset -U path PATH
path=("$HOME/.local/bin" $path)
export PATH EDITOR=nvim VISUAL=nvim
# ~/.zprofile
source "$HOME/.config/zsh/environment.zsh"
# ~/.zshrc
if [[ ! -o login ]]; then
  source "$HOME/.config/zsh/environment.zsh"
fi

# Interactive-only configuration follows.

Este padrão mantém os dados partilhados separados dos efeitos laterais do login. Outra opção válida é configurar de forma consistente o terminal ou o gestor de sessões, em vez de suportar ambos os modos.

Diagnostique a shell lenta ou sem estado

Reproduza diretamente cada modo:

zsh -lic 'print "login interactive"'
zsh -ic  'print "non-login interactive"'
zsh -lc  'print "login non-interactive"'
zsh -c   'print "non-login non-interactive"'

Meça o modo que os utilizadores iniciam efetivamente:

time zsh -lic exit
time zsh -ic exit

Rastreie a execução de ficheiros e linhas quando a origem não for clara:

PS4='%N:%i> ' zsh -xlic exit

Execute o trace numa conta de teste limpa ou inspecione-o antes de o partilhar: os comandos de arranque podem expandir tokens e outros valores sensíveis.

Para um executável em falta, inspecione tanto o modo como o path:

print -r -- "interactive=$options[interactive] login=$options[login]"
print -l -- $path

Conclusão

A distinção útil não é «ambiente versus aliases». É estado exclusivo de login versus estado interativo, acrescido da pequena quantidade de configuração que tem realmente de afetar todos os processos Zsh.

Confirme as flags da shell, mantenha os ficheiros de arranque silenciosos e coloque cada hook gerado onde todas as funcionalidades necessárias estejam disponíveis. Assim, a configuração torna-se portátil entre aplicações de terminal, sem fingir que o macOS e o Linux têm, cada um, um único modo fixo de arranque.

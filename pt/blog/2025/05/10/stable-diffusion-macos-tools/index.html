Stable Diffusion no macOS: comparação de ferramentas locais de geração de imagens

Viacheslav Dubrov

2025-05-10 · Atualizado 2026-07-15 · 7 min · Ferramentas de desenvolvimento

Tradução automática Este artigo foi traduzido automaticamente a partir da versão original em inglês.

Executar modelos de imagem localmente no macOS é, sobretudo, uma questão de escolher as ferramentas certas. Draw Things, DiffusionBee, ComfyUI, AUTOMATIC1111 e Fooocus sobrepõem-se em várias áreas, mas diferem na configuração, no suporte de modelos, no controlo do workflow, nas extensões e na automatização.

Uma aplicação de arrastar e largar permite começar rapidamente; um grafo de nós demora mais tempo a aprender, mas expõe uma parte maior do pipeline. No Apple Silicon, a aplicação, a família do modelo, a precisão, o tamanho da imagem e o workflow influenciam a possibilidade de a geração caber na memória. Escolha a interface com base no trabalho que precisa de reproduzir e, em seguida, teste o modelo e as definições exatos.

Em resumo. Comece pelo Draw Things ou pelo DiffusionBee quando uma aplicação nativa for suficiente para o trabalho. Use o ComfyUI quando for necessário inspecionar, partilhar ou automatizar o próprio grafo. Escolha o AUTOMATIC1111 apenas para workflows que dependam da respetiva interface ou das suas extensões. Encare o Fooocus como um workflow estável da era do SDXL, não como uma via para obter suporte para modelos atuais: o projeto oficial encontra-se em suporte de longo prazo limitado.

Um ficheiro de modelo não é um workflow portátil

Várias aplicações conseguem carregar ficheiros .safetensors, mas uma extensão de ficheiro compatível não significa que o modelo irá funcionar. Um pipeline completo pode também exigir uma arquitetura, um text encoder, um VAE, um scheduler, um ControlNet, um LoRA, um tokenizer ou uma configuração específica da aplicação.

Registe tudo o que produziu uma imagem:

  • aplicação e versão
  • repositório do modelo, revisão e licença
  • todos os componentes do modelo e adapters
  • prompt, negative prompt, seed, sampler, steps, guidance e dimensões
  • ficheiro do grafo ou do workflow, quando a aplicação disponibilizar um

Este registo é mais importante do que a popularidade da aplicação. A mesma seed pode ainda produzir uma imagem diferente após uma alteração do backend, do modelo, do sampler ou da precisão.

A memória unificada é partilhada, não ilimitada

O Apple Silicon permite que a CPU e a GPU acedam ao mesmo pool de memória. Isso elimina uma fronteira de cópia separada, mas o macOS e todas as aplicações abertas competem pela mesma capacidade.

Na geração de imagens, o pico de utilização inclui mais do que os pesos do checkpoint:

peak memory ≈ model components
            + intermediate activations
            + attention and runtime workspace
            + loaded adapters and control models
            + application and OS memory

A resolução, o tamanho do batch, a arquitetura do modelo, a precisão, o upscaling, o ControlNet e o facto de os componentes permanecerem carregados alteram o resultado. Não compre nem escolha uma máquina com base numa tabela universal de «8/16/32 GB». Teste o workflow pretendido e monitorize a pressão de memória. Uma geração que só tem sucesso através de swap contínuo não constitui um ponto de operação confortável.

Draw Things: interação nativa e scripting

Draw Things é uma aplicação para plataformas Apple destinada à geração local de imagens. A documentação atual abrange modelos, LoRAs, ControlNet, textual inversion, Core ML e scripting JavaScript com versões.

Escolha-a quando o trabalho deve permanecer dentro de uma aplicação nativa, mas ainda requer mais controlo do que uma caixa de prompt. Antes de a adotar como padrão, importe os componentes exatos do modelo e reproduza uma edição, um adapter ou um workflow de controlo representativo. «Nativa» descreve a interface e a implementação; não garante suporte nem velocidade para todas as arquiteturas novas.

DiffusionBee: workflow macOS empacotado

DiffusionBee reúne a transferência de modelos e as tarefas de geração comuns numa aplicação de desktop. A documentação do projeto lista image-to-image, inpainting, outpainting, ControlNet, LoRA e SDXL. As notas de lançamento do DiffusionBee 2.5.3 indicam suporte para Flux.1 apenas em Macs arm64 com macOS 13 ou posterior.

Escolha-o quando a instalação e uma UI integrada forem mais importantes do que exportar um grafo de pipeline. Verifique o lançamento mais recente e a arquitetura exata antes de transferir um modelo grande. Uma etiqueta de funcionalidade como «suporte para Flux» não significa que todas as variantes, quantizações ou componentes auxiliares possam ser carregados.

ComfyUI: o workflow é um artefacto

ComfyUI representa a geração como um grafo de nós. Um workflow pode ser armazenado como JSON independentemente do resultado, o que torna o pipeline inspecionável e versionável. O seu executor também pode evitar recalcular secções do grafo cujas entradas não tenham sido alteradas.

A versão atual do ComfyUI Desktop suporta Apple Silicon e gere o seu próprio ambiente, embora a documentação oficial para macOS ainda classifique o Desktop como beta. Está disponível uma instalação através do Homebrew:

brew install comfyui

Escolha o ComfyUI quando um pipeline tiver ramificações, componentes reutilizáveis, vários modelos ou automação. Mantenha juntos o JSON, a versão da aplicação, as versões dos core nodes, as revisões dos custom nodes e o manifesto de modelos.

Os custom nodes são dependências executáveis. Analise o respetivo código-fonte e os scripts de instalação, fixe as revisões e isole o ambiente. Um grafo de um autor desconhecido pode referenciar código e modelos que ainda não auditou.

AUTOMATIC1111: compatibilidade com uma Web UI consolidada

AUTOMATIC1111 Stable Diffusion WebUI disponibiliza as definições de geração através de uma interface no browser e suporta scripts, extensões e uma API. Escolha-o quando um tutorial específico, uma automação ou uma extensão já fizer parte dos requisitos.

O guia oficial para Apple Silicon documenta exceções e limitações de desempenho, incluindo um desempenho fraco no treino. Confirme que a funcionalidade necessária funciona nas versões de macOS e PyTorch de destino antes de adotar uma configuração com muitas extensões.

As extensões executam código dentro do ambiente da aplicação. Fixe as versões, analise as atualizações e mantenha o serviço ligado apenas ao loopback, salvo se o acesso remoto for intencional e estiver protegido.

Fooocus: uma opção limitada da era do SDXL

Fooocus oculta deliberadamente muitas escolhas técnicas por detrás de um workflow orientado para prompts e com opiniões predefinidas. Isso pode ser útil quando os respetivos valores predefinidos correspondem à tarefa.

O README atual do projeto indica que o Fooocus é desenvolvido em torno do SDXL e está num regime de suporte de longo prazo limitado, apenas com correções de bugs. Indica também que o Mac não é testado intensivamente e descreve a instalação no Mac como não oficial. Assim, o Fooocus é uma escolha limitada para um workflow Fooocus existente, não o caminho predefinido para novas arquiteturas ou para uma configuração macOS que pretenda manter.

Execute um teste de aceitação representativo

Utilize um pequeno conjunto de aceitação antes de se comprometer com uma ferramenta:

  1. Reproduza um resultado de texto-para-imagem de referência a partir de uma seed e definições registadas.
  2. Execute a operação obrigatória mais exigente: inpainting, ControlNet, LoRA, upscale ou um grafo com várias etapas.
  3. Reinicie a aplicação e reproduza o workflow a partir dos artefactos guardados.
  4. Meça o arranque a frio, o tempo de geração, a pressão máxima sobre a memória e as dimensões da saída.
  5. Transfira o workflow para uma conta de utilizador ou máquina limpa e registe todas as dependências em falta.
  6. Verifique a ligação à rede local, as transferências, as definições de analytics, as licenças e a proveniência dos modelos.

Não compare ferramentas com checkpoints, resoluções, contagens de steps ou precisão diferentes e depois chame ao resultado um benchmark de runtime.

Uma predefinição prática

Para trabalho exploratório, comece por uma aplicação nativa e por um modelo que a própria aplicação documente. Passe para o ComfyUI quando o próprio workflow se tornar valioso: quando tiver de ser revisto, repetido, automatizado ou entregue a outra pessoa. Mantenha o AUTOMATIC1111 ou o Fooocus quando uma dependência existente tornar útil a respetiva interface específica.

O que vale a pena conservar é o pacote reproduzível mais pequeno de identidades dos modelos, parâmetros, dependências e estado do workflow capaz de produzir novamente o resultado.

Stable Diffusion op macOS: lokale image tools vergeleken

Viacheslav Dubrov

2025-05-10 · Bijgewerkt 2026-07-15 · 6 min · Ontwikkelaarstools

Automatische vertaling Dit artikel is automatisch vertaald vanuit de oorspronkelijke Engelse versie.

Image models lokaal draaien op macOS is vooral een keuze van tooling. Draw Things, DiffusionBee, ComfyUI, AUTOMATIC1111 en Fooocus overlappen elkaar, maar verschillen in setup, modelondersteuning, workflowcontrole, extensies en automatisering.

Met een drag-and-drop-app kun je snel beginnen; een node graph kost meer tijd om te leren, maar maakt een groter deel van de pipeline inzichtelijk. Op Apple Silicon bepalen de applicatie, model family, precision, image size en workflow allemaal of generation in het geheugen past. Kies de interface op basis van het werk dat je moet reproduceren en test daarna het exacte model en de exacte instellingen.

TL;DR. Begin met Draw Things of DiffusionBee wanneer een native applicatie de taak afdekt. Gebruik ComfyUI wanneer de graph zelf moet worden geïnspecteerd, gedeeld of geautomatiseerd. Kies AUTOMATIC1111 alleen voor een workflow die afhankelijk is van de interface of extensies. Beschouw Fooocus als een stabiele workflow uit het SDXL-tijdperk, niet als route naar ondersteuning voor huidige modellen: het officiële project bevindt zich in beperkte long-term support.

Een model file is geen portable workflow

Verschillende applicaties kunnen .safetensors-files laden, maar een overeenkomende file extension betekent niet dat het model werkt. Een complete pipeline kan ook een specifieke architecture, text encoder, VAE, scheduler, ControlNet, LoRA, tokenizer of application-specific configuration vereisen.

Leg alles vast waarmee een image is geproduceerd:

  • applicatie en versie
  • model repository, revision en license
  • elk model component en elke adapter
  • prompt, negative prompt, seed, sampler, steps, guidance en dimensions
  • graph- of workflowfile wanneer de applicatie die beschikbaar stelt

Dit overzicht is belangrijker dan de populariteit van de app. Dezelfde seed kan nog steeds een andere image produceren na een wijziging in backend, model, sampler of precision.

Unified memory wordt gedeeld, maar is niet onbeperkt

Apple Silicon zorgt ervoor dat de CPU en GPU één memory pool kunnen adresseren. Daarmee verdwijnt een afzonderlijke kopieergrens, maar macOS en elke geopende applicatie concurreren om dezelfde capaciteit.

Bij image generation omvat peak use meer dan alleen de checkpoint weights:

peak memory ≈ model components
            + intermediate activations
            + attention and runtime workspace
            + loaded adapters and control models
            + application and OS memory

Resolution, batch size, model architecture, precision, upscaling, ControlNet en de vraag of componenten geladen blijven, veranderen allemaal het resultaat. Koop of selecteer geen machine op basis van een universele tabel met “8/16/32 GB”. Test de beoogde workflow en houd memory pressure in de gaten. Een generation die alleen lukt door langdurig gebruik van swap is geen comfortabel operating point.

Draw Things: native interactie en scripting

Draw Things is een Apple-platformapplicatie voor lokale image generation. De huidige documentatie behandelt models, LoRAs, ControlNet, textual inversion, Core ML en versioned JavaScript scripting.

Kies deze optie wanneer het werk binnen een native applicatie moet blijven, maar meer controle vereist dan een prompt box biedt. Importeer voordat je erop standaardiseert de exacte model components en reproduceer één representatieve edit-, adapter- of control-workflow. “Native” beschrijft de interface en implementatie; het garandeert geen ondersteuning of snelheid voor elke nieuwe architecture.

DiffusionBee: verpakte macOS-workflow

DiffusionBee verpakt model download en veelgebruikte generationtasks in een desktopapplicatie. De projectdocumentatie vermeldt image-to-image, inpainting, outpainting, ControlNet, LoRA en SDXL. De release notes van DiffusionBee 2.5.3 melden Flux.1-ondersteuning alleen op arm64-Macs met macOS 13 of hoger.

Kies deze optie wanneer installatiegemak en een geïntegreerde UI belangrijker zijn dan het exporteren van een pipeline graph. Controleer de nieuwste release en de exacte architecture voordat je een groot model downloadt. Een featurelabel zoals “Flux support” betekent niet dat elke derivative, quantization of auxiliary component kan worden geladen.

ComfyUI: de workflow is een artefact

ComfyUI representeert generation als een node graph. Een workflow kan onafhankelijk van de output als JSON worden opgeslagen, waardoor de pipeline inspecteerbaar en versioneerbaar wordt. De executor kan bovendien voorkomen dat graph-secties opnieuw worden berekend wanneer hun inputs niet zijn gewijzigd.

De huidige ComfyUI Desktop-build ondersteunt Apple Silicon en beheert zijn eigen environment, hoewel de officiële macOS-documentatie Desktop nog steeds als beta aanduidt. Een Homebrew-installatie is beschikbaar:

brew install comfyui

Kies ComfyUI wanneer een pipeline branches, herbruikbare components, meerdere models of automatisering bevat. Bewaar de JSON, applicatieversie, versies van core nodes, revisions van custom nodes en het model manifest bij elkaar.

Custom nodes zijn uitvoerbare dependencies. Review hun source en install scripts, pin revisions en isoleer de environment. Een graph van een onbekende auteur kan verwijzen naar code en models die je niet hebt geaudit.

AUTOMATIC1111: compatibiliteit met een gevestigde Web UI

AUTOMATIC1111 Stable Diffusion WebUI stelt generation settings beschikbaar via een browserinterface en ondersteunt scripts, extensies en een API. Kies deze optie wanneer een specifieke tutorial, automatisering of extensie al onderdeel van de requirements is.

De officiële Apple Silicon-guide documenteert uitzonderingen en performancebeperkingen, waaronder zwakke training performance. Controleer of de vereiste feature werkt met de doelversies van macOS en PyTorch voordat je een setup met veel extensies invoert.

Extensies draaien code binnen de application environment. Pin ze, review updates en houd de service op loopback tenzij remote access bewust is ingeschakeld en beveiligd.

Fooocus: een begrensde optie uit het SDXL-tijdperk

Fooocus verbergt bewust veel technische keuzes achter een opinionated, prompt-first workflow. Dat kan nuttig zijn wanneer de defaults bij de taak passen.

De huidige README van het project vermeldt dat Fooocus rond SDXL is gebouwd en zich in beperkte long-term support bevindt, met alleen bug fixes. Ook staat er dat Mac niet intensief wordt getest en dat de Mac-installatie unofficial is. Daarmee is Fooocus een begrensde keuze voor een bestaande Fooocus-workflow, niet de standaardroute voor nieuwe architectures of voor een macOS-setup die je wilt onderhouden.

Voer één representatieve acceptance test uit

Gebruik één kleine acceptance set voordat je je aan een tool commit:

  1. Reproduceer een baseline text-to-image-resultaat met een vastgelegde seed en settings.
  2. Voer de moeilijkste vereiste operatie uit: inpainting, ControlNet, LoRA, upscale of een multi-stage graph.
  3. Start de applicatie opnieuw en reproduceer de workflow vanuit opgeslagen artefacts.
  4. Meet cold start, generation time, peak memory pressure en output dimensions.
  5. Verplaats de workflow naar een schoon user account of een andere machine en noteer elke ontbrekende dependency.
  6. Controleer local-network binding, downloads, analytics settings, licenses en model provenance.

Vergelijk tools niet met verschillende checkpoints, resolutions, step counts of precision en noem het resultaat daarna geen runtime benchmark.

Een praktische default

Begin voor exploratief werk met een native app en een model dat daarin wordt gedocumenteerd. Stap over op ComfyUI wanneer de workflow zelf waardevol wordt: wanneer die moet worden gereviewd, herhaald, geautomatiseerd of aan iemand anders moet worden overgedragen. Houd AUTOMATIC1111 of Fooocus aan wanneer een bestaande dependency hun specifieke surface nuttig maakt.

Wat de moeite waard is om te bewaren, is het kleinste reproduceerbare pakket van model identities, parameters, dependencies en workflow state waarmee je het resultaat opnieuw kunt produceren.

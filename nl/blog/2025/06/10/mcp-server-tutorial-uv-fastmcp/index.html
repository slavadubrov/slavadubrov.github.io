MCP-serverhandleiding met uv en FastMCP: Een FeatureStoreLite-server bouwen

Deze MCP-serverhandleiding bouwt een kleine feature-store-server met FastMCP, draait deze met uv en koppelt hem aan Claude Desktop.

Kort samengevat: Een kleine FastMCP-server is voldoende om een bruikbaar lokaal hulpprogramma beschikbaar te stellen voor een agent. Gebruik uv voor een reproduceerbare opstelling, houd de servergrenzen beperkt, valideer invoer met getypeerde schema’s en test het MCP-hulpprogramma voordat je het koppelt aan een model.

Wat is een MCP-server?

Het Model Context Protocol (MCP) is een open standaard voor het verbinden van AI-assistenten met externe gegevens en hulpprogramma’s. Het vervangt aparte, aangepaste integraties voor elk hulpprogramma door één set conventies.

In deze handleiding bouwen we een FeatureStoreLite-MCP-server. Deze server bevindt zich tussen een LLM en een feature-store (een database met vooraf berekende ML-features) en biedt hulpprogramma’s om featurevectoren te zoeken en te schrijven, waarbij de vectoren worden gecodeerd op basis van gebruiker, product of document.

Waarom dit bouwen?

Je bent een ML-engineer die een pipeline debugt. In plaats van SQL te gebruiken of een snel script te schrijven om featurewaarden te controleren, kun je rechtstreeks aan Claude vragen: “Wat is de featurevector voor gebruiker_123?” of “Laat me de metadata van product_abc zien.” De MCP-server maakt dit mogelijk.

Waarom uv gebruiken?

We gebruiken uv om pakketten te installeren, afhankelijkheden op te lossen en het virtuele omgevingbeheer uit te voeren. Later zal uv run --with mcp[cli] ... ook in staat stellen de Claude Desktop-configuratie direct de benodigde afhankelijkheden te specificeren. Dit voorkomt dat er een aparte omgeving ontstaat die uit balans kan raken.

Overzicht van de architectuur

De vier componenten en hoe ze met elkaar samenwerken:

  1. De gebruiker stelt een vraag in natuurlijke taal.
  2. Claude Desktop fungeert als MCP-client. Het kiest een hulpprogramma op basis van de vraag en roept dit aan.
  3. Onze FastMCP-server biedt get_feature en store_feature aan als MCP-hulpprogramma’s.
  4. SQLite dient als back-endopslag voor de featurevectoren.

3. De server bouwen

Twee bestanden, gescheiden naar functie:

  1. database.py handelt de SQLite-operaties af.
  2. featurestore_server.py definieert de MCP-server.

3.1. De databaselaag (database.py)

Dit module beheert de SQLite-verbinding en enkele hulpprogramma’s. We vullen de database met twee voorbeeldregels zodat de server iets kan teruggeven bij de eerste query.

Maak database.py aan:

# database.py
import json
import os
import sqlite3


def get_db_path() -> str:
    """Get the database path - always in the script's directory"""
    script_dir = os.path.dirname(os.path.abspath(__file__))
    return os.path.join(script_dir, "features.db")


def init_db() -> None:
    """Initialize the feature store database with table and sample data"""
    conn = sqlite3.connect(get_db_path())
    conn.execute("""
        CREATE TABLE IF NOT EXISTS features (
            key TEXT PRIMARY KEY,
            vector TEXT NOT NULL,
            metadata TEXT,
            created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
        )
    """)

    # Sample data for experimentation
    example_features = [
        (
            "user_123",
            "[0.1, 0.2, -0.5, 0.8, 0.3, -0.1, 0.9, -0.4]",
            json.dumps({"type": "user", "id": 123, "segment": "premium"}),
        ),
        (
            "product_abc",
            "[0.7, -0.3, 0.4, 0.1, -0.8, 0.6, 0.2, -0.5]",
            json.dumps({"type": "product", "id": "abc", "category": "electronics"}),
        ),
    ]

    # Insert if not exists
    for key, vector, metadata in example_features:
        try:
            conn.execute(
                "INSERT INTO features (key, vector, metadata) VALUES (?, ?, ?)",
                (key, vector, metadata),
            )
        except sqlite3.IntegrityError:
            pass  # Already exists

    conn.commit()
    conn.close()


def get_db_connection() -> sqlite3.Connection:
    """Get a database connection"""
    return sqlite3.connect(get_db_path())


if __name__ == "__main__":
    init_db()
    print("✅ Database initialized successfully!")

Initialiseer de database:

uv run python database.py

3.2. De MCP-server (featurestore_server.py)

FastMCP verricht het grootste deel van het werk. Decoréer een gewone Python-functie en deze wordt geregistreerd als een MCP-hulpmiddel of -resource. De docstring vormt de beschrijving die de LLM ziet, dus schrijf deze gericht op een LLM, niet alleen voor mensen.

Maak featurestore_server.py aan:

# featurestore_server.py
import json
from mcp.server.fastmcp import FastMCP
from database import get_db_connection, init_db

# Initialize the MCP Server
mcp = FastMCP("FeatureStoreLite")

# Ensure DB is ready when server starts
init_db()


@mcp.resource("schema://main")
def get_schema() -> str:
    """
    Resource: Provide the database schema.
    Resources are passive data that LLMs can read like files.
    """
    conn = get_db_connection()
    try:
        schema = conn.execute(
            "SELECT sql FROM sqlite_master WHERE type='table'"
        ).fetchall()
        return "\n".join(sql[0] for sql in schema if sql[0]) or "No tables found."
    finally:
        conn.close()


@mcp.tool()
def store_feature(key: str, vector: str, metadata: str | None = None) -> str:
    """
    Tool: Store a feature vector.
    Tools are executable functions that LLMs can call to perform actions.
    """
    conn = get_db_connection()
    try:
        # Validate that vector is valid JSON
        json.loads(vector)

        conn.execute(
            "INSERT OR REPLACE INTO features (key, vector, metadata) VALUES (?, ?, ?)",
            (key, vector, metadata),
        )
        conn.commit()
        return f"Successfully stored feature '{key}'"
    except json.JSONDecodeError:
        return "Error: Vector must be a valid JSON array string (e.g., '[0.1, 0.2]')"
    except Exception as e:
        return f"Error: {str(e)}"
    finally:
        conn.close()


@mcp.tool()
def get_feature(key: str) -> str:
    """
    Tool: Retrieve a feature vector by key.
    """
    conn = get_db_connection()
    try:
        row = conn.execute(
            "SELECT vector, metadata FROM features WHERE key = ?", (key,)
        ).fetchone()

        if row:
            return json.dumps(
                {
                    "key": key,
                    "vector": json.loads(row[0]),
                    "metadata": json.loads(row[1]) if row[1] else None,
                },
                indent=2,
            )
        return f"Feature '{key}' not found."
    finally:
        conn.close()


@mcp.tool()
def list_features() -> str:
    """
    Tool: List all available feature keys.
    """
    conn = get_db_connection()
    try:
        rows = conn.execute("SELECT key FROM features").fetchall()
        return json.dumps([row[0] for row in rows])
    finally:
        conn.close()


if __name__ == "__main__":
    mcp.run()

5. Verbinden met Claude Desktop

Zodra de Inspector bevestigt dat de server werkt, registreer je hem bij Claude Desktop.

5.1. Claude configureren

Editeer het configuratiebestand van Claude Desktop:

  • macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
  • Windows: %APPDATA%/Claude/claude_desktop_config.json

Voeg je server toe aan het mcpServers-object:

{
    "mcpServers": {
        "featurestore": {
            "command": "uv",
            "args": [
                "run",
                "--with",
                "mcp[cli]",
                "mcp",
                "run",
                "/ABSOLUTE/PATH/TO/mcp-featurestore/featurestore_server.py"
            ]
        }
    }
}

Belangrijk: de pad naar featurestore_server.py moet absoluut zijn. Een relatief pad zal stilletjes falen omdat Claude Desktop wordt uitgevoerd vanuit een andere werkmap.

5.2. Hoe de interactie werkt

Hieronder staat wat er van begin tot eind gebeurt wanneer Claude een zoekopdracht naar een functie moet uitvoeren:

  1. Claude ziet de beschikbare hulpmiddelen (get_feature, list_features, enzovoort).
  2. Het beslist dat de vraag gegevens uit de feature-store nodig heeft.
  3. Het bouwt een oproep voor een hulpmiddel op en stuurt deze naar je server.
  4. De server voert de Python-functie uit en geeft het resultaat terug.
  5. Claude gebruikt dit resultaat om het uiteindelijke antwoord op te stellen.

6. Probleemoplossing

Enkele veelvoorkomende fouten waar je rekening mee moet houden:

  • “Serververbinding is mislukt”:

    • Controleer de logbestanden op ~/Library/Logs/Claude/mcp.log op macOS.
    • Zorg ervoor dat de configuratie een absoluut pad gebruikt, geen relatief pad.
    • Controleer of uv zich bevindt op de PATH van Claude Desktop. Is dit niet het geval, wijs dan op het volledige binairpad (which uv laat zien waar het zich bevindt).

  • “Fout bij uitvoering van hulpmiddel”:

    • Repliceer het probleem in de Inspector met uv run mcp dev featurestore_server.py. De Inspector toont de oorspronkelijke fout, die Claude Desktop meestal verbergt.
    • Controleer of features.db wordt gegenereerd naast database.py. Als je werkmap verandert, zorgt het scriptrelatieve pad in get_db_path() ervoor dat alles nog werkt.

7. Conclusie

Dit is alles: een FastMCP-server, een SQLite-backingstore, en een Claude Desktop-configuratie die verwijst naar een uv run-commando. Hetzelfde principe is bruikbaar voor alles wat in een Python-functie kan worden opgenomen. Vervang de SQLite-oproepen door een echte feature-store, een interne API of een modelregister, zonder dat de server groter wordt.

Belangrijkste punten

  1. MCP vormt een grens voor tools, maar is geen reden om elke interne functie te exposeren.
  2. Houd de serversoftware klein, getypeerd en gemakkelijk te testen, zelfs zonder een LLM.
  3. Gebruik uv zodat de leeromgeving vanaf nul opnieuw kan worden opgebouwd.
  4. Beschouw de MCP-server als productiecoder zodra een agent deze kan aanroepen.

Het verhaal rond tooling veranderde in 2025–2026. MCP, het Model Context Protocol, gaf vendors één gedeelde manier om externe services beschikbaar te maken. TL;DR

Vijf bruikbare interfacepatronen dekken het grootste deel van tool use door agents. Skills bevatten instructies, CLI tools passen bij lokale development, MCP verbindt gedeelde services en code-executie composeert multi-step werk binnen een sandbox. JSON tool calling blijft de eenvoudigste keuze voor kleine atomic actions. Ongeacht het protocol moet de Agent-Computer Interface (ACI) acties duidelijk maken, feedback compact houden en errors herstelbaar maken.

Vijf manieren waarop AI agents tools gebruiken

In deel 1 koos de reasoning loop de volgende stap. Deel 2 sloeg de state op die nodig was om verder te gaan. De tool boundary zit tussen beide: die valideert wat de loop heeft voorgesteld, geeft de call door voor uitvoering en retourneert het resultaat aan de loop. Deze vijf patronen maken verschillende trade-offs op het gebied van tokenkosten, flexibiliteit en enforcement.

1. JSON tool calling: de baseline

Het oorspronkelijke patroon: je definieert tool schemas als JSON, de LLM produceert structured function calls en je code voert ze uit. Het patroon is goed begrepen en werkt prima voor kleine toolsets.

# Traditional tool definition — each tool consumes ~550-1,400 tokens (Apideck benchmark)
tools = [
    {
        "name": "get_stock_price",
        "description": "Get the current stock price for a ticker symbol",
        "input_schema": {
            "type": "object",
            "properties": {
                "ticker": {"type": "string", "description": "Stock ticker (e.g., NVDA)"}
            },
            "required": ["ticker"]
        }
    }
]

Bij 5–10 tools is de overhead acceptabel. Het probleem ontstaat bij schaal: elke tooldefinitie kost 550–1.400 tokens. Bij 20 tools besteed je 11–28K tokens voordat de agent überhaupt begint met reasoning.

2. MCP voor gedeelde integrations

MCP is de standaard waar de meeste vendors naartoe zijn geconvergeerd. Een MCP server is een process dat via een gedefinieerd wire protocol een lijst tools adverteert — stdio voor een lokaal process, HTTP voor een remote process. Je agent draait een MCP client die verbinding maakt, de server vraagt welke tools beschikbaar zijn en de calls van het model doorstuurt, zodat dezelfde server werkt met elke client die het protocol ondersteunt. Anthropic schonk het protocol in december 2025 aan de Linux Foundation, onder de Agentic AI Foundation die het samen met OpenAI en Block oprichtte. Google, Microsoft en AWS steunen de foundation als platinum members. OpenAI voegde MCP support toe aan zijn Responses API. Volgens Anthropic’s aankondiging van de donatie in december 2025 telde het ecosysteem 10.000+ actieve publieke MCP servers en 97M+ maandelijkse SDK downloads via de Python- en TypeScript-SDKs.

MCP past bij cross-vendor SaaS integration (Figma, Notion, Salesforce), services zonder CLI-equivalenten en omgevingen die OAuth orchestration nodig hebben. De waarde zit in een gedeelde discovery- en transportlaag. Governance blijft afhankelijk van de authentication-, authorization-, logging- en deployment-controls van de server.

Het production-verhaal is rommeliger dan de headline-cijfers suggereren.

Het security-oppervlak is het eerste probleem. Het Vulnerable MCP Project volgt 50 vulnerabilities in MCP servers, waarvan 13 als Critical zijn beoordeeld, aangedragen door 32 security researchers. Attack classes omvatten prompt injection, fouten in input validation, authentication gaps en gaten in network security. De eerste kwaadaardige MCP server in de praktijk verscheen in september 2025: een package met de naam postmark-mcp dat elke uitgaande e-mail BCC’de naar het adres van een aanvaller. Naar schatting werden 300–500 organisaties getroffen voordat het package werd ontdekt.

Tool poisoning is de attack class waar ik me het meeste zorgen over maak. Invariant Labs demonstreerde dat poisoned MCP tools data kunnen exfiltreren zonder ooit te worden aangeroepen. Het model hoeft alleen de metadata van de tool te lezen om de attack te activeren. MCPTox benchmarks, waarin 20 LLM agents tegen 45 MCP servers uit de praktijk werden getest, vonden attack success rates tot 72,8%.

Tokenoverhead is het operationele probleem. Een team dat MCP servers voor GitHub, Slack en Sentry draaide (in totaal ongeveer 40 tools) ontdekte dat 55.000 tokens aan schemadefinities werden geïnjecteerd voordat een gebruiker iets had gevraagd. Een ander team rapporteerde dat 143.000 van de 200.000 beschikbare tokens (72%) alleen door tooldefinities werden verbruikt.

Anthropic rapporteerde een reductie van 85% in tokens voor tooldefinities met zijn Tool Search Tool — ongeveer 77.000 tokens aan schemas teruggebracht naar 8.700 — door alleen de drie tot vijf tools te laden die een request daadwerkelijk nodig heeft. Selective loading behoudt het protocoloppervlak en verwijdert tegelijk schemas die de huidige request niet nodig heeft.

3. Skills verpakken expertise, geen execution

Eind 2025 kwam de standaardisatie van agent skills als open format (gelanceerd in oktober 2025 en in december 2025 gepubliceerd als open standard). Tools bieden capabilities (wat agents kunnen doen) en skills bieden expertise (wat agents weten over hoe ze complexe taken moeten uitvoeren).

Het SKILL.md-format definieert een skill als een markdownbestand met YAML frontmatter. De open standard vereist alleen name en description; het onderstaande voorbeeld gebruikt daarnaast twee Claude Code extensions, argument-hint en user-invocable, plus de positional-argument-placeholder $0:

---
name: deploy
description: Deploy the application to production
argument-hint: "[environment]"
user-invocable: true
---
Deploy the application to the $0 environment (default: staging).
Steps:
1. Run the test suite
2. Build the production bundle
3. Deploy using the deploy script
4. Verify the deployment health check

Skills gebruiken progressive disclosure. Bij startup wordt ongeveer 100 tokens aan metadata geladen; volledige instructies worden pas geladen wanneer de skill actief is. Vergelijk dat met de ongeveer 55.000 tokens die ongeveer 40 MCP tools kunnen verbruiken voordat reasoning begint.

In maart 2026 hadden Claude Code, OpenAI Codex CLI, Cursor, GitHub Copilot, Gemini CLI, Goose, Devin Desktop (toen Windsurf) en Roo Code het format overgenomen. Skills maken deel uit van een bredere beweging richting codegedreven agent actions, die Victor Dibia traceert van JSON function calls naar gegenereerde code — het patroon dat sectie 5 behandelt.

Gebruik skills voor domain knowledge, multi-step procedures en terugkerend werk zoals database migrations of payment integrations. Ze passen bij taken waarbij de agent instructies nodig heeft over hoe hij een bestaande capability moet gebruiken.

4. CLI- en shell tools

CLI interfaces kunnen in de context veel goedkoper zijn wanneer het model het command al kent. Scalekit rapporteerde over 75 runs een verschil van 4–32x in tokens tussen zijn CLI- en MCP-paden. Die case study meet zijn eigen tools en taken; ze vervangt geen vergelijking met je eigen tooldefinities en command output.

Goed gedocumenteerde commands zoals git, docker, kubectl, gh, curl en jq hebben vaak weinig introductietekst in hun schema nodig. Minder gebruikelijke of interne CLIs hebben nog steeds discoverable help, voorbeelden en stabiele machine-readable output nodig.

Ugo Enyioha’s gids “Writing CLI Tools That AI Agents Actually Want to Use” legde acht ontwerpregels vast:

  1. Structured output is verplicht — ondersteun --json
  2. Exit codes zijn control flow — gebruik verschillende codes voor verschillende error types
  3. Commands moeten idempotent zijn
  4. Self-documenting --help met realistische voorbeelden
  5. Ontwerp voor composability — --quiet voor bare values, ondersteuning voor stdin
  6. Bied --dry-run- en --yes-flags
  7. Ondersteun version introspection
  8. Verwerk auth via environment variables

CLI mist de type safety, ingebouwde OAuth orchestration, tool discovery en audit trail van MCP. Het patroon waar de meeste teams op uitkomen is: CLI als default voor development en lokale operations, MCP voor externe service integration en enterprise governance.

5. Code-executie voor multi-step werk

Dit is de verandering in agent tooling die ik het meest consequential vind. In plaats van structured JSON te produceren om vooraf gedefinieerde functions één voor één aan te roepen, schrijft de agent een Python- of bash-script. Het script roept meerdere tools aan, verwerkt resultaten met loops en conditionals en retourneert alleen de uiteindelijke samenvatting naar de modelcontext.

Anthropic formaliseerde dit met Programmatic Tool Calling (PTC), dat inmiddels algemeen beschikbaar is in de Claude API. De academische basis is de CodeAct-paper (Wang et al., ICML 2024), waarin 17 LLMs werden getest. Daarin bereikten code actions tot 20% hogere task success rates en 30% minder steps dan JSON-alternatieven.

Drie first-party case studies laten zien waar het patroon kan helpen: hieronder Vercel en Cloudflare, gevolgd door Anthropic’s voorbeeld voor expense analysis. Beschouw ze als vendor evidence en voer de vergelijking opnieuw uit op je eigen taken.

  • Vercel herbouwde d0, zijn data agent die natuurlijke taal naar SQL vertaalt, en bracht het aantal tools terug van 15 naar 2 — ExecuteCommand en ExecuteSQL — een reductie die hun post afrondt op 80%. Over vijf representatieve queries steeg task success van 4/5 naar 5/5, daalde de gemiddelde execution time met 3,5x (274,8 s naar 77,4 s) en nam het gemiddelde tokengebruik met 37% af (~102K naar ~61K). Hun formulering: “De beste agents zijn misschien degene met de minste tools.”

  • Cloudflare ontwikkelde “Code Mode,” waarmee agents TypeScript kunnen schrijven om hun API aan te roepen in plaats van tool schemas te definiëren, waardoor de contextoverhead afneemt. Hun redenering: “LLMs hebben enorm veel TypeScript uit de praktijk in hun trainingsset, maar slechts een kleine hoeveelheid geconstrueerde voorbeelden van tool calls.”

Hier volgt het patroon uit Anthropic’s PTC-documentatie. Traditionele tool calling voor expense analysis vereist meer dan 20 afzonderlijke inference passes, één per teamlid, waarbij alle intermediate data door de context stroomt. Anthropic rapporteert dat gegenereerde code voor dezelfde vraag de data die de context bereikt terugbrengt van 200 KB aan onbewerkte expense rows — meer dan 2.000 line items — naar 1 KB aan resultaten. Met code-executie schrijft de agent één script:

# Agent generates this code, executes in sandbox
import json
members = get_team_members("engineering")
over_budget = []
for m in members:
    expenses = get_expenses(m["id"], "Q3")
    total = sum(e["amount"] for e in expenses)
    if total > 5000:
        custom = get_custom_budget(m["id"])
        limit = custom["limit"] if custom else 5000
        if total > limit:
            over_budget.append({"name": m["name"], "spent": total, "limit": limit})
# Only this final summary returns to the LLM context
print(json.dumps(over_budget))

De LLM ziet alleen de uiteindelijke JSON summary, niet de duizenden expense line items die in de sandbox zijn verwerkt. De besparing is niet specifiek voor expense reports: Anthropic’s afzonderlijke write-up over code-executie geeft het scherpste cijfer voor dit patroon: een Google Drive-to-Salesforce-workflow daalde van ongeveer 150.000 tokens naar ongeveer 2.000, een reductie van 98,7%.

Tokenefficiëntie is de meest voor de hand liggende winst. Loops en conditionals kosten niets extra’s, errors lopen via try/except in plaats van via natural-language reasoning over failures en gevoelige data blijft in de sandbox.

Wanneer JSON tool calling nog steeds zinvol is: voor single atomic operations, omgevingen zonder sandboxing-infrastructure, kleinere models met zwakke codegeneratie of auditvereisten waarbij elke afzonderlijke tool invocation moet worden gelogd.

De Agent-Computer Interface (ACI) voor AI-agenttools

De term “Agent-Computer Interface” (ACI) werd bedacht door John Yang, Carlos E. Jimenez en collega’s aan Princeton in hun SWE-agent-paper (NeurIPS 2024). De kwaliteit van human interfaces heeft een volledige discipline die eraan is gewijd — human-computer interaction, oftewel HCI. De paper stelt dat language-model agents dezelfde behandeling verdienen: ze zijn “een nieuwe categorie eindgebruikers met hun eigen behoeften en vaardigheden, en zouden baat hebben bij speciaal ontworpen interfaces.”

Hun ablation results maken dat meetbaar. Met hetzelfde GPT-4 Turbo-basemodel bereikte de SWE-bench Lite-ablation in de paper 18,0% met SWE-agent’s volledige ACI op 300 taken, tegenover 7,3% voor de shell-only conditie zonder worked demonstration en 11,0% met één demonstration. De vergelijking laat zien dat de interface- en demonstrationcondities de performance in deze setup materieel veranderden; ze isoleert interface design niet van elk ander verschil en laat niet zien dat het model geen werk deed. Binnen dezelfde interface-ablation verhoogde linting de edit-conditie van 15,0% naar 18,0%; over de volledige SWE-bench-testset raakte 51,7% van de SWE-agent-runs minstens één edit die de linter afwees voordat die kon worden doorgezet.

Anthropic nam ACI over als een fundamenteel concept in zijn gids “Building Effective Agents”, waar het als een van drie kernprincipes wordt genoemd: “Ontwerp je agent-computer interface zorgvuldig met grondige tooldocumentatie en testing.” De praktische richtlijn luidt: “Een vuistregel is om na te denken over hoeveel effort er in human-computer interfaces gaat en van plan te zijn evenveel effort te investeren in het creëren van goede agent-computer interfaces.”

Vier ACI-principes in de praktijk

1. Acties moeten eenvoudig en gemakkelijk te begrijpen zijn. De meest voorkomende fout is het één-op-één wrappen van API endpoints. Implementeer in plaats van list_users, list_events en create_event één schedule_event die availability vindt en in één call inplant. Implementeer in plaats van read_logs één search_logs die alleen de relevante regels met context retourneert.

2. Acties moeten compact en efficiënt zijn. Consolideer belangrijke operations in zo weinig mogelijk acties. In de Market Analyst Agent combineer ik het ophalen van prijzen met basismetrics in één get_stock_snapshot-tool, in plaats van afzonderlijke calls te vereisen voor price, volume, market cap en PE ratio.

3. Feedback uit de omgeving moet informatief maar beknopt zijn. Retourneer geen raw HTML of volledige API payloads. Vertaal cryptische IDs naar semantic names. Anthropic’s testing voegde een response_format-enum toe, zodat de agent om een beknopte (~72 tokens) of gedetailleerde (~206 tokens) response kan vragen — ongeveer een verschil van 3x in tokenkosten.

4. Validation moet error propagation beperken. Automatic error detection helpt agents fouten snel te herkennen en te corrigeren. In SWE-agent weigert een custom file editor met geïntegreerde linting automatisch syntax errors — de validationstap achter het bovenstaande cijfer van 51,7%. Dit is validation op de inputs en outputs van een tool, niet de content filtering rond een model call die de guardrail-products in deel 4 uitvoeren; hetzelfde woord wordt voor beide gebruikt. Ik pas hetzelfde principe toe in de Market Analyst Agent door tool arguments vóór execution met Pydantic schemas te valideren:

from pydantic import BaseModel, Field, field_validator

class StockQuery(BaseModel):
    """Validated input for stock queries.

    Pydantic catches malformed tickers before the API call,
    preventing error propagation through the reasoning loop.
    """
    ticker: str = Field(description="Stock ticker symbol (e.g., NVDA)")
    period: str = Field(default="1mo", description="Time period: 1d, 5d, 1mo, 3mo, 6mo, 1y")

    @field_validator("ticker")
    @classmethod
    def validate_ticker(cls, v: str) -> str:
        v = v.upper().strip()
        if not v.isalpha() or len(v) > 5:
            raise ValueError(f"Invalid ticker format: {v}")
        return v

    @field_validator("period")
    @classmethod
    def validate_period(cls, v: str) -> str:
        valid = {"1d", "5d", "1mo", "3mo", "6mo", "1y"}
        if v not in valid:
            raise ValueError(f"Invalid period: {v}. Must be one of {valid}")
        return v

AI-agent tool design patterns die werken

Anthropic’s gids “Writing effective tools for agents” beschrijft tools als “een nieuw soort software die een contract weerspiegelt tussen deterministische systemen en niet-deterministische agents.”

Behandel toolbeschrijvingen als prompt engineering

Beschrijvingen moeten minstens drie of vier zinnen bevatten en aangeven wanneer de tool moet worden gebruikt, welke parameters verplicht of optioneel zijn, wat het output format is en welke edge cases bestaan. Anthropic rapporteert dat de keuze tussen prefix- en suffix-based namespacing (asana_search versus search_asana) “niet-triviale effecten” had op zijn eigen tool-use evals. Er wordt niet gezegd welk schema wint; test daarom beide op je toolset in plaats van prefixes vanzelfsprekend te vinden. Anthropic voerde ook de transcripts van zijn evaluation agents terug naar Claude Code en liet het de tools herschrijven. Op held-out testsets vond die loop verdere verbeteringen, “zelfs boven wat we bereikten met ‘expert’ tool implementations” — ongeacht of die tools handmatig door researchers waren geschreven of door Claude waren gegenereerd.

# Bad: vague, no context for when to use
tools = [{
    "name": "search",
    "description": "Search for items",
}]

# Good: specific, with input examples and edge cases
tools = [{
    "name": "search_news",
    "description": (
        "Search for recent news articles about a specific stock or company. "
        "Use this tool when the user asks about recent events, earnings, "
        "announcements, or market-moving news for a specific ticker. "
        "Returns up to 10 articles sorted by relevance. "
        "For company competitors rather than news, use search_competitors instead."
    ),
    "input_schema": {
        "type": "object",
        "properties": {
            "query": {
                "type": "string",
                "description": "Search query. Examples: 'NVDA earnings Q3 2025', 'Tesla delivery numbers'"
            },
            "max_results": {
                "type": "integer",
                "description": "Max articles to return (1-10, default 5)",
                "default": 5
            }
        },
        "required": ["query"]
    }
}]

Anthropic’s interne testing liet zien dat het toevoegen van een input_examples-field de accuracy bij complexe parameter handling verhoogde van 72% naar 90%.

Retourneer high-signal, machine-readable output

Vermijd low-level identifiers (uuid, mime_type). Vertaal cryptische IDs naar semantic names. Structureer de response zo dat de agent erover kan reasonen zonder boilerplate te hoeven parsen:

# Bad: raw API response dumped to agent
def get_stock_snapshot(ticker: str) -> dict:
    response = api.get(f"/v1/quotes/{ticker}")
    return response.json()  # 500+ tokens of nested JSON

# Good: high-signal summary the agent can immediately reason about
def get_stock_snapshot(ticker: str) -> dict:
    data = api.get(f"/v1/quotes/{ticker}").json()
    return {
        "ticker": ticker,
        "price": data["regularMarketPrice"],
        "change_pct": round(data["regularMarketChangePercent"], 2),
        "volume": data["regularMarketVolume"],
        "market_cap_b": round(data["marketCap"] / 1e9, 1),
        "pe_ratio": data.get("trailingPE"),
        "summary": f"{ticker} at ${data['regularMarketPrice']:.2f} "
                   f"({'up' if data['regularMarketChangePercent'] > 0 else 'down'} "
                   f"{abs(data['regularMarketChangePercent']):.1f}%)"
    }

Retourneer errors waarop de loop kan handelen

Error handling heeft vier afzonderlijke mechanisms nodig, omdat ze verschillende failure classes afhandelen:

  1. Retry met exponential backoff voor transient errors
  2. Model fallback chains bij provider outages
  3. Error-classification routing — transient errors worden opnieuw geprobeerd, LLM-recoverable errors gaan met context terug naar de agent en errors waarvoor een mens nodig is worden geëscaleerd
  4. Checkpoint recovery om crashes te overleven

Anthropic’s “Writing effective tools for agents” pleit voor duidelijke tool errors en evaluation-driven tool design, maar geeft geen universeel getal voor wat deze vier mechanisms herstellen. Meet recovery rate, retries en escalations op je eigen task suite.

import httpx
from tenacity import retry, stop_after_attempt, wait_exponential

@retry(
    stop=stop_after_attempt(3),
    wait=wait_exponential(multiplier=1, min=2, max=10),
)
def call_stock_api(ticker: str) -> dict:
    """Fetch stock data with automatic retry on transient failures.

    Mechanism 1 of the four above: exponential backoff for rate limits
    and network blips.
    If all retries fail, the error propagates to the agent with
    enough context to decide whether to try a different approach.
    """
    response = httpx.get(
        f"https://api.example.com/v1/quotes/{ticker}",
        timeout=10.0,
    )
    response.raise_for_status()
    return response.json()

De patronen toepassen op de Market Analyst Agent

De Market Analyst Agent uit deel 1 maakt het effect van de interface zichtbaar.

Tool consolidation

Het oorspronkelijke design had meer dan 10 tools: get_stock_price, get_company_metrics, get_market_cap, get_pe_ratio, get_volume enzovoort. Elk daarvan was een dunne wrapper rond één API endpoint. De agent moest voor elk request reasonen over de combinatie die moest worden aangeroepen.

Ik consolideerde het market-data-oppervlak tot 5 high-level tools, volgens het ACI-principe van compacte, efficiënte acties. De ReAct-tool list in de repo bevat daarnaast nog vier tools — een skill loader, twee CLI wrappers en een beperkte in-process Python evaluator (een AST-allowlist, geen sandbox; deel 4 gaat hierop in) — waarmee drie van de vijf bovenstaande modaliteiten worden afgedekt. MCP verschijnt als sidecar en niet als tool in deze lijst:

Structured outputs voor tool results

Elke tool in de Market Analyst Agent retourneert een door Pydantic gevalideerde response. Hiermee pas ik het ACI-validationprincipe toe op de output van de tool:

class StockSnapshot(BaseModel):
    """Structured tool response — the agent never sees raw API noise."""
    ticker: str
    price: float
    change_pct: float
    volume: int
    market_cap_b: float
    pe_ratio: float | None
    summary: str  # Human-readable one-liner for direct use in reports

class NewsResult(BaseModel):
    """Each news item is pre-processed for agent consumption."""
    headline: str
    source: str
    date: str
    relevance_score: float  # Pre-ranked so the agent doesn't waste tokens sorting
    key_points: list[str]  # Extracted by the tool, not the agent

Het summary-field is het belangrijkst. Het geeft de agent een direct bruikbare string die zonder extra verwerking in een report kan worden geplaatst. De key_points in NewsResult worden door de tool geëxtraheerd en niet door de agent, zodat de agent geen inference tokens hoeft te besteden aan het parsen van article bodies.

Trade-offs en overwegingen

Naast de caveats die specifiek zijn voor elk hierboven beschreven patroon, zijn er enkele cross-cutting concerns die de keuze bepalen:

  • Operationele kosten variëren per dimensie. Code-executie bespaart tokens, maar voegt sandbox cold-start latency toe. MCP bespaart developmenttijd voor SaaS integrations, maar voegt overhead voor server deployment toe. CLI is kosteloos om mee te starten, maar op schaal moeilijker te governen. Optimaliseer voor je werkelijke bottleneck, of dat nu tokenkosten, latency of operationele complexiteit is.

  • Teamvaardigheden zijn belangrijk. Code-executie veronderstelt dat je agents (en de models erachter) betrouwbare Python of TypeScript kunnen genereren. CLI veronderstelt bekendheid met Unix-conventies. MCP vereist inzicht in transportprotocols en OAuth flows. Stem de modality af op de sterke punten van je team.

  • Tool consolidation kan te ver gaan. Als één tool niet-gerelateerde modes en arguments verzamelt, krijgt de agent binnen het schema een ander selectieprobleem. Gebruik tool-selection- en task-success-evals om het juiste oppervlak voor je workload te vinden.

  • Skills zijn prompt-based, niet enforced. Een skill bevat instructies die de agent zou moeten volgen, geen guardrails die de agent moet volgen. Combineer skills voor kritieke workflows met deterministische validation.

  • Auditvereisten beïnvloeden de keuze. Als je een volledig log nodig hebt van elke tool invocation en het resultaat ervan, bieden MCP en JSON tool calling direct structured audit trails. Code-executie produceert een script en de output ervan, wat nuttig is maar moeilijker op te splitsen in individuele acties voor compliance reporting.

Drie richtingen voor AI-agenttooling op schaal

De eerste is tool RAG voor scaling. Wanneer toolsets groeien naar honderden of duizenden tools, daalt de accuracy van naive tool selection naar 13,62%. De RAG-MCP-paper paste retrieval-augmented generation toe op tool selection: indexeer de toolbeschrijvingen in een vector database en haal per query alleen de relevante tools op. Dat bereikte een accuracy van 43,13%, een verbetering van 3,2x, en verlaagde tegelijk het aantal prompt tokens met ongeveer 50%.

De tweede is dat agents hun eigen tools creëren. Het LATM-framework (“LLMs As Tool Makers”) introduceerde een two-phase paradigm waarin een krachtige LLM herbruikbare Python functions maakt en een lightweight LLM ze gebruikt. ToolMaker (ACL 2025) transformeert GitHub repositories autonoom in LLM-compatible tools met een success rate van 80%. Beide wijzen voorbij tool use, richting tool creation en vervolgens het beheren van een library met gegenereerde tools.

De derde is de dual-protocol stack van A2A + MCP. Het Agent2Agent Protocol (A2A), gecreëerd door Google en in juni 2025 geschonken aan de Linux Foundation, adresseert wat MCP niet kan: agent-to-agent communication. MCP handelt agent-to-tool integration af; A2A handelt agent-to-agent discovery, negotiation en task delegation af.

Belangrijkste conclusies

  1. Kies de interface op basis van de actie: JSON calling voor kleine typed operations, MCP voor gedeelde services, Skills voor procedures, CLI voor gevestigde commands en sandboxed code voor lokale compositie.
  2. Houd benchmarkcondities gekoppeld aan het resultaat. CodeAct, Anthropic, Vercel, Cloudflare, Apideck en Scalekit maten verschillende models, tasks, tools en harnesses.
  3. ACI-kwaliteit blijft overeind bij protocolwijzigingen. Duidelijke acties, compacte feedback, validation en bruikbare errors helpen bij elke modality.
  4. Consolideer overlappende tools alleen wanneer evals laten zien dat het kleinere oppervlak tool selection of task success verbetert.
  5. Security beweegt mee met execution power. Shell- en codeinterfaces hebben sandboxing nodig; MCP heeft scoped identity en server policy nodig; Skills blijven instructies en zijn geen enforcement.

De volgende laag is policy

Deel 4, AI Agent Security, plaatst een policy check tussen een voorgestelde tool call en execution. Het is dezelfde tool boundary die hierboven is beschreven, maar nu bekeken vanuit de kant die nee zegt. Deel 5 plaatst de tool en zijn sandbox vervolgens in een recoverable runtime, en deel 6 voegt een tweede contract toe dat het model nooit ziet: een effect category, een retry rule en een structured result die een acceptance check kan lezen zonder prose te hoeven parsen.

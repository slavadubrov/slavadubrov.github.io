Stable Diffusion на macOS: сравнение локальных инструментов для генерации изображений

Viacheslav Dubrov

2025-05-10 · Обновлено 2026-07-15 · 5 мин · Инструменты разработчика

Автоматический перевод Эта статья была автоматически переведена с оригинальной английской версии.

Запуск image-моделей локально на macOS — в основном вопрос выбора инструментов. Draw Things, DiffusionBee, ComfyUI, AUTOMATIC1111 и Fooocus во многом пересекаются, но различаются установкой, поддержкой моделей, управлением пайплайнами, расширениями и автоматизацией.

Приложение с drag-and-drop позволяет быстро начать работу, а node graph требует больше времени на освоение, зато открывает доступ к большему числу этапов пайплайна. На Apple Silicon на то, поместится ли генерация в память, влияют приложение, семейство моделей, точность, размер изображения и сам workflow. Выбирайте интерфейс под задачи, которые нужно воспроизводить, а затем тестируйте конкретную модель и настройки.

Кратко. Начните с Draw Things или DiffusionBee, если для задачи достаточно нативного приложения. Используйте ComfyUI, когда сам graph нужно проверять, передавать другим или автоматизировать. Выбирайте AUTOMATIC1111 только для workflow, зависящего от его интерфейса или расширений. Рассматривайте Fooocus как стабильный workflow эпохи SDXL, а не как путь к поддержке современных моделей: официальный проект находится в режиме ограниченного долгосрочного сопровождения.

Файл модели — это не переносимый workflow

Несколько приложений умеют загружать файлы .safetensors, но одинаковое расширение файла ещё не означает, что модель заработает. Для полного пайплайна также могут потребоваться определённая архитектура, текстовый энкодер, VAE, scheduler, ControlNet, LoRA, tokenizer или конфигурация, специфичная для приложения.

Фиксируйте всё, что участвовало в создании изображения:

  • приложение и его версию
  • репозиторий модели, ревизию и лицензию
  • каждый компонент модели и адаптер
  • промпт, negative prompt, seed, sampler, число шагов, guidance и размеры
  • graph или файл workflow, если приложение его поддерживает

Эта информация важнее популярности приложения. Один и тот же seed всё равно может дать другое изображение после изменения бэкенда, модели, sampler или точности.

Unified memory общая, но не безграничная

Apple Silicon позволяет CPU и GPU обращаться к единому пулу памяти. Это устраняет границу между отдельными копиями, но macOS и все открытые приложения конкурируют за один и тот же объём.

При генерации изображений пиковое потребление включает не только веса чекпоинта:

peak memory ≈ model components
            + intermediate activations
            + attention and runtime workspace
            + loaded adapters and control models
            + application and OS memory

Разрешение, размер batch, архитектура модели, точность, апскейлинг, ControlNet и то, остаются ли компоненты загруженными, — всё это меняет результат. Не покупайте и не выбирайте машину по универсальной таблице «8/16/32 GB». Тестируйте предполагаемый workflow и следите за memory pressure. Генерация, которая выполняется только за счёт длительного использования swap, — некомфортный рабочий режим.

Draw Things: нативное взаимодействие и скриптинг

Draw Things — приложение для платформ Apple, предназначенное для локальной генерации изображений. В его актуальной документации описаны модели, LoRA, ControlNet, textual inversion, Core ML и версионируемый JavaScript-скриптинг.

Выбирайте его, когда работа должна оставаться в нативном приложении, но требует большего контроля, чем простое поле промпта. Прежде чем стандартизировать этот инструмент, импортируйте нужные компоненты модели и воспроизведите одну репрезентативную операцию редактирования, работу адаптера или control-workflow. «Нативность» описывает интерфейс и реализацию, но не гарантирует поддержку или скорость для каждой новой архитектуры.

DiffusionBee: пакетный workflow для macOS

DiffusionBee объединяет загрузку моделей и распространённые задачи генерации в desktop-приложении. В документации проекта перечислены image-to-image, inpainting, outpainting, ControlNet, LoRA и SDXL. В release notes DiffusionBee 2.5.3 указано, что Flux.1 поддерживается только на arm64 Mac с macOS 13 или новее.

Выбирайте его, когда установка и интегрированный UI важнее экспорта graph пайплайна. Перед загрузкой большой модели проверьте последний релиз и точную архитектуру. Такая отметка, как «поддержка Flux», не означает, что загрузятся любые производные модели, квантизации или вспомогательные компоненты.

ComfyUI: workflow — это артефакт

ComfyUI представляет генерацию в виде node graph. Workflow можно хранить в JSON отдельно от результата, благодаря чему пайплайн становится проверяемым и пригодным для версионирования. Его executor также может не пересчитывать участки graph, входные данные которых не изменились.

Текущая сборка ComfyUI Desktop поддерживает Apple Silicon и самостоятельно управляет своим окружением, хотя в официальной документации для macOS Desktop по-прежнему помечен как beta. Доступна установка через Homebrew:

brew install comfyui

Выбирайте ComfyUI, когда в пайплайне есть ветвления, переиспользуемые компоненты, несколько моделей или автоматизация. Храните вместе JSON, версию приложения, версии core nodes, ревизии custom nodes и манифест моделей.

Custom nodes — это исполняемые зависимости. Проверяйте их исходный код и скрипты установки, фиксируйте ревизии и изолируйте окружение. Graph от неизвестного автора может обращаться к коду и моделям, которые вы не проверяли.

AUTOMATIC1111: совместимость с устоявшимся Web UI

AUTOMATIC1111 Stable Diffusion WebUI предоставляет настройки генерации через браузерный интерфейс и поддерживает скрипты, расширения и API. Выбирайте его, когда конкретный tutorial, автоматизация или расширение уже входят в требования.

В официальном руководстве для Apple Silicon описаны исключения и ограничения производительности, включая слабую производительность обучения. Прежде чем внедрять конфигурацию с большим числом расширений, убедитесь, что нужная функция работает на целевых версиях macOS и PyTorch.

Расширения запускают код внутри окружения приложения. Фиксируйте их версии, проверяйте обновления и оставляйте сервис доступным только через loopback, если удалённый доступ не предусмотрен намеренно и не защищён.

Fooocus: ограниченный вариант эпохи SDXL

Fooocus намеренно скрывает многие технические настройки за opinionated workflow, ориентированным прежде всего на промпт. Это удобно, если его defaults подходят для задачи.

В текущем README проекта сказано, что Fooocus построен вокруг SDXL и находится в режиме ограниченного долгосрочного сопровождения, получая только исправления ошибок. Там же указано, что Mac не проходил интенсивное тестирование, а установка на Mac описана как неофициальная. Поэтому Fooocus — ограниченный выбор для уже существующего workflow на Fooocus, а не вариант по умолчанию для новых архитектур или macOS-конфигурации, которую вы планируете поддерживать.

Проведите один репрезентативный acceptance-тест

Перед тем как остановиться на инструменте, используйте небольшой acceptance-набор:

  1. Воспроизведите базовый результат text-to-image по сохранённым seed и настройкам.
  2. Запустите самую сложную обязательную операцию: inpainting, ControlNet, LoRA, апскейлинг или многоэтапный graph.
  3. Перезапустите приложение и воспроизведите workflow по сохранённым артефактам.
  4. Измерьте холодный старт, время генерации, пиковую memory pressure и размеры результата.
  5. Перенесите workflow в чистую учётную запись пользователя или на другую машину и перечислите все отсутствующие зависимости.
  6. Проверьте привязку к локальной сети, загрузки, настройки аналитики, лицензии и происхождение моделей.

Не сравнивайте инструменты с разными чекпоинтами, разрешениями, числом шагов или точностью, а затем не называйте результат бенчмарком рантайма.

Практический вариант по умолчанию

Для исследовательской работы начните с нативного приложения и модели, которую оно документирует. Переходите на ComfyUI, когда ценность начинает представлять сам workflow: когда его нужно проверять, повторять, автоматизировать или передавать другому человеку. Оставайтесь на AUTOMATIC1111 или Fooocus, если существующая зависимость делает их специфический интерфейс полезным.

Сохранять стоит минимальный воспроизводимый комплект идентификаторов моделей, параметров, зависимостей и состояния workflow, который позволяет снова получить тот же результат.

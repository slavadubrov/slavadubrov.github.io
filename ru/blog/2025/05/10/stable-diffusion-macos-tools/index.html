Stable Diffusion на macOS: Draw Things, DiffusionBee, ComfyUI, A1111 и Fooocus

Запуск image models локально на macOS — в основном вопрос выбора туллинга. Draw Things, DiffusionBee, ComfyUI, AUTOMATIC1111 и Fooocus пересекаются по возможностям, но различаются по установке, поддержке моделей, контролю над воркфлоу, расширениям и степени автоматизации.

Drag-and-drop приложение помогает быстро начать; node graph придется дольше освоить, зато он сильнее «раскрывает» пайплайн. На Apple Silicon приложение, семейство моделей, точность (precision), размер изображения и сам воркфлоу определяют, поместится ли генерация в память. Выбирайте интерфейс под то, что нужно воспроизвести, затем прогоните точную модель и настройки.

TL;DR. Начинайте с Draw Things или DiffusionBee, если нативное приложение закрывает задачу. Используйте ComfyUI, когда нужно инспектировать, шарить или автоматизировать сам graph. AUTOMATIC1111 выбирайте только для воркфлоу, которое зависит от его интерфейса или расширений. Fooocus рассматривайте как стабильный воркфлоу эпохи SDXL, а не как путь к актуальной поддержке моделей: у официального проекта ограниченный long-term support.

Файл модели — не переносимый воркфлоу

Несколько приложений могут загружать .safetensors файлы, но совпадение расширения еще не гарантирует работоспособность модели. Полный пайплайн может дополнительно требовать конкретную архитектуру, text encoder, VAE, scheduler, ControlNet, LoRA, tokenizer или конфигурацию, специфичную для приложения.

Зафиксируйте все, что использовалось для генерации изображения:

  • приложение и версия
  • репозиторий модели, ревизия и лицензия
  • каждый компонент модели и адаптер
  • prompt, negative prompt, seed, sampler, steps, guidance и dimensions
  • graph или workflow файл, если приложение его предоставляет

Этот трекинг важнее популярности приложения. Один и тот же seed может дать другое изображение после изменения backend, модели, sampler или precision.

Unified memory общий, но не бесконечный

Apple Silicon позволяет CPU и GPU адресовать один пул памяти. Это убирает отдельную границу копирования, но macOS и каждое открытое приложение конкурируют за тот же объем.

Для image generation пиковое потребление включает не только веса checkpoint:

peak memory ≈ model components
            + intermediate activations
            + attention and runtime workspace
            + loaded adapters and control models
            + application and OS memory

Разрешение, batch size, архитектура модели, precision, upscaling, ControlNet и то, остаются ли компоненты загруженными — все это меняет результат. Не покупайте и не выбирайте машину по универсальной таблице «8/16/32 GB». Протестируйте целевой воркфлоу и следите за давлением на память. Генерация, которая «успешна» только за счет длительного swap, — плохая рабочая точка с точки зрения комфортности эксплуатации.

Draw Things: нативное взаимодействие и скриптинг

Draw Things — приложение для локальной генерации изображений под Apple-платформы. Текущая документация покрывает модели, LoRAs, ControlNet, textual inversion, Core ML и версионированный JavaScript scripting.

Выбирайте его, когда работу нужно держать внутри нативного приложения, но при этом требуется больше контроля, чем дает prompt box. Перед стандартизацией на нем импортируйте точные компоненты модели и воспроизведите один репрезентативный edit, adapter или control workflow. «Native» описывает интерфейс и реализацию; это не гарантирует поддержку и скорость для каждой новой архитектуры.

DiffusionBee: упакованный macOS workflow

DiffusionBee упаковывает загрузку моделей и типовые generation задачи в desktop-приложение. Документация проекта перечисляет image-to-image, inpainting, outpainting, ControlNet, LoRA, SDXL и выбранную поддержку Flux.

Выбирайте его, когда установка и интегрированный UI важнее экспорта пайплайна в виде graph. Проверьте latest release и точную архитектуру перед загрузкой большой модели. Метка фичи вроде «Flux support» не означает, что загрузятся все производные, квантизация или вспомогательные компоненты.

ComfyUI: воркфлоу — артефакт

ComfyUI представляет генерацию как node graph. Воркфлоу можно хранить как JSON независимо от результата, поэтому пайплайн инспектируем и версионируем. Его executor также может избегать пересчета секций graph, если входные данные не менялись.

Текущая сборка ComfyUI Desktop поддерживает Apple Silicon и управляет собственным окружением, хотя официальная macOS документация все еще маркирует Desktop как beta. Доступна установка через Homebrew:

brew install comfyui

Выбирайте ComfyUI, когда у пайплайна есть ветвления, переиспользуемые компоненты, несколько моделей или нужна автоматизация. Держите вместе JSON, версию приложения, версии core-node, ревизии custom-node и модельный манифест.

Custom nodes — исполняемые зависимости. Ревьюьте их исходники и install scripts, фиксируйте ревизии и изолируйте окружение. Graph от неизвестного автора может ссылаться на код и модели, которые вы не аудировали.

AUTOMATIC1111: совместимость с устоявшимся Web UI

AUTOMATIC1111 Stable Diffusion WebUI предоставляет настройки генерации через браузерный интерфейс и поддерживает scripts, extensions и API. Выбирайте его, когда конкретный туториал, автоматизация или extension уже является частью требований.

Официальный гайд по Apple Silicon документирует исключения и ограничения по производительности, включая слабую обучающую performance. Подтвердите, что требуемая фича работает на целевых версиях macOS и PyTorch, прежде чем переходить на setup с множеством расширений.

Extensions выполняют код внутри среды приложения. Фиксируйте их, ревьюьте обновления и держите сервис на loopback, если удаленный доступ не предусмотрен осознанно и не защищен.

Fooocus: ограниченный вариант эпохи SDXL

Fooocus намеренно прячет многие технические выборы за мнение-зависимым workflow «prompt-first». Это может быть полезно, если ее дефолты совпадают с задачей.

В текущем README проекта сказано, что Fooocus построен вокруг SDXL и находится в limited long-term support с исправлениями только багов. Также сказано, что Mac не интенсивно тестируется, а установку на Mac описывают как неофициальную. Поэтому Fooocus — это ограниченный выбор для уже существующего Fooocus workflow, а не default-путь для новых архитектур или для macOS-сетапа, который вы планируете поддерживать.

Прогоните один приемочный тест

Перед фиксацией туллинга прогоните небольшой acceptance set:

  1. Воспроизведите baseline text-to-image результат по зафиксированным seed и settings.
  2. Выполните самое сложное требуемое действие: inpainting, ControlNet, LoRA, upscale или multi-stage graph.
  3. Перезапустите приложение и воспроизведите workflow по сохраненным артефактам.
  4. Замерьте cold start, время генерации, пиковое давление на память и размеры выхода.
  5. Перенесите workflow в чистую учетку пользователя или на другую машину и перечислите все отсутствующие зависимости.
  6. Проверьте binding в локальной сети, настройки загрузок/аналитики, лицензии и provenance модели.

Не сравнивайте туллинги с разными checkpoint, разрешениями, количеством шагов или precision и затем называйте это runtime benchmark.

Практичный дефолт

Для исследовательской работы начните с нативного приложения и модели, которую оно документирует. Переходите на ComfyUI, когда само воркфлоу начинает быть ценным: когда его нужно ревьюить, повторять, автоматизировать или передавать другому человеку. AUTOMATIC1111 или Fooocus оставляйте, если у вас уже есть существующая зависимость, которая делает их конкретную поверхность удобной.

Сохранять стоит самый маленький воспроизводимый пакет: идентичности моделей, параметры, зависимости и состояние воркфлоу, который снова дает тот же результат.

Файлы запуска Zsh: ~/.zprofile против ~/.zshrc на macOS и Linux

Если терминал работает медленно или какая‑то переменная среды видна в одном терминале, но отсутствует в другом, причиной часто является режим запуска Zsh. Самыми популярными файлами для настройки считаются ~/.zprofile и ~/.zshrc, однако одного только имени файла недостаточно, чтобы определить, следует ли та или иная строка туда помещаться.

Zsh выбирает файлы запуска на основе двух независимых критериев: является ли оболочка оболочкой входа и интерактивной ли она. Приложения терминалов на macOS и Linux могут использовать разные комбинации этих параметров, поэтому необходимо проверять текущую оболочку, а не полагаться на решение операционной системы.

Кратко. Настройки, связанные с сессией входа, размещайте в .zprofile, а параметры интерактивного режима — в .zshrc. Файл .zshenv должен оставаться максимально простым и без действий. Не перемещайте хуки управления версионными менеджерами в .zprofile и не подключайте весь профиль из .zshrc; изучите код, генерируемый инструментом, и следуйте его текущим указаниям для Zsh.

Zsh учитывает два независимых флага

Оболочка может быть:

  • оболочкой входа и интерактивной, так как Apple Terminal обычно запускает стандартную оболочку входа пользователя;
  • необолочкой входа и интерактивной, как это происходит при использовании вложенных zsh или многих конфигураций терминалов Linux;
  • оболочкой входа и неинтерактивной, как в случае zsh -lc 'command';
  • необолочкой входа и неинтерактивной, как в случае zsh -c 'command'.

Приложения терминалов, IDE, удалённые сессии, мультиплексоры и явные флаги оболочки могут задавать разные режимы. Операционная система сама по себе не определяет этот параметр.

Вместо догадок проверяйте текущую оболочку:

print -r -- "interactive=$options[interactive] login=$options[login]"

Фактический порядок запуска

Сначала Zsh читает глобальные файлы, затем соответствующие пользовательские файлы. При стандартных значениях RCS порядок чтения пользовательских файлов выглядит следующим образом:

  1. $ZDOTDIR/.zshenv при каждом запуске Zsh;
  2. $ZDOTDIR/.zprofile если оболочка является оболочкой входа;
  3. $ZDOTDIR/.zshrc если оболочка интерактивна;
  4. $ZDOTDIR/.zlogin если оболочка является оболочкой входа;
  5. $ZDOTDIR/.zlogout при нормальном завершении работы оболочки входа.

Если ZDOTDIR не установлен, Zsh использует $HOME. Местоположения файлов в системе определяются конкретной версией ОС; распространённые стандартные пути — /etc/zshenv, /etc/zprofile, /etc/zshrc, /etc/zlogin и /etc/zlogout.

Этот порядок является лишь фильтром, а не гарантией всего жизненного цикла оболочки. .zprofile выполняется один раз на каждый процесс оболочки входа, а не один раз при каждом входе в систему. Если каждая новая вкладка терминала запускает оболочку входа, каждая вкладка будет её читать.

Сохраняйте .zshenv простым

Каждый неконфликтный zsh -c загружает .zshenv. Наличие здесь echo, вызовов менеджера пакетов или ресурсоёмких подпроцессов может повредить результат выполнения команды и замедлить работу скриптов. Большинству пользователей в этом файле нужно либо совсем ничего, либо минимум.

Экспортированная переменная в .zprofile наследуется дочерними процессами данного шелла входа. Она не вставляется автоматически в не связанные с ним GUI-приложения, сервисы или шеллы, чей родительский процесс никогда не читал этот файл.

Используйте .zprofile для настройки только при входе

Небольшой профиль может содержать экспортированные значения по умолчанию и идемпотентный путь:

# ~/.zprofile
export EDITOR=nvim
export VISUAL=nvim

# Zsh ties the path array to the PATH scalar.
typeset -U path PATH
path=("$HOME/.local/bin" $path)
export PATH

typeset -U удаляет дублирующиеся элементы массива. Это делает повторную загрузку безопаснее, однако файлы запуска всё равно должны избегать ненужных операций.

Используйте .zshrc для хранения интерактивного состояния

# ~/.zshrc
setopt auto_cd hist_ignore_all_dups share_history

autoload -Uz compinit
compinit

alias ll='ls -lah'
bindkey -e

Псевдонимы, компоненты автодополнения, карты клавиш, промпты и хуки изменения каталога относятся к интерактивному шеллу, который их использует.

Менеджеры версий пересекают простые границы файлов

Совет «Размещайте менеджеры версий в .zprofile, потому что они медленные» ненадёжен. Менеджер версий может генерировать несколько типов кода:

  • статический путь или переменная корня;
  • путь к shim-команде, необходимой дочерним процессам;
  • определения для автодополнения;
  • функции шелла, изменяющие текущий шелл;
  • хуки изменения каталога для автоматической смены версии.

Интерактивные компоненты должны присутствовать в каждом интерактивном шелле, включая вложенный zsh, запущенный из редактора. Поэтому текущая документация fnm размещает этот хук в .zshrc:

eval "$(fnm env --use-on-cd --shell zsh)"

Аналогично, текущая документация pyenv также помещает полную интерактивную инициализацию в .zshrc:

export PYENV_ROOT="$HOME/.pyenv"
[[ -d $PYENV_ROOT/bin ]] && path=("$PYENV_ROOT/bin" $path)
eval "$(pyenv init - zsh)"

Документация Pyenv описывает более узкий режим pyenv init --path для настройки shim-path, однако полная версия pyenv init также устанавливает функции автодополнения и обработки команд в шелле. Перед разделением кода необходимо изучить текущую документацию инструмента и результаты его работы.

Если время запуска слишком велико, сначала измерьте его, прежде чем переводить код в режим, в котором он уже не будет функционировать.

Не загружайте весь профиль из .zshrc

Распространённым решением, работающим в разных операционных системах, является:

# Avoid this blanket coupling.
source ~/.zprofile

Это преобразует действия, доступные только при входе в систему, в действия, выполняемые в каждом интерактивном шелле, что может привести к повторному запуску ИИ-агента, получению доступа к ключевой книге, выводу данных или изменению путей.

Если как интерактивные шеллы с входом в систему, так и без него нуждаются в небольшом наборе статических экспортов, извлеките идемпотентный фрагмент и загружайте его явно:

# ~/.config/zsh/environment.zsh
typeset -U path PATH
path=("$HOME/.local/bin" $path)
export PATH EDITOR=nvim VISUAL=nvim
# ~/.zprofile
source "$HOME/.config/zsh/environment.zsh"
# ~/.zshrc
if [[ ! -o login ]]; then
  source "$HOME/.config/zsh/environment.zsh"
fi

# Interactive-only configuration follows.

Такой подход позволяет сохранять общие данные отдельно от эффектов, связанных с входом в систему. Другим вариантом является единообразная настройка терминала или менеджера сессий вместо поддержки обоих режимов.

Диагностика медленного шелла или отсутствия состояния

Попробуйте запустить каждый режим напрямую:

zsh -lic 'print "login interactive"'
zsh -ic  'print "non-login interactive"'
zsh -lc  'print "login non-interactive"'
zsh -c   'print "non-login non-interactive"'

Измерьте тот режим, который фактически используют пользователи:

time zsh -lic exit
time zsh -ic exit

При неясности источника проблемы отслеживайте выполнение файлов и строк:

PS4='%N:%i> ' zsh -xlic exit

Запустите отслеживание в чистом тестовом аккаунте или изучите результаты перед их передачей — команды запуска могут расширять токены и другие конфиденциальные значения.

Если отсутствует исполняемый файл, проверьте как сам режим, так и указанный путь:

print -r -- "interactive=$options[interactive] login=$options[login]"
print -l -- $path
whence -va python node uv

Заключение

Полезное различие заключается не в «среде против псевдонимов», а в состоянии, доступном только при входе в систему, и интерактивном состоянии, плюс в небольшом количестве элементов, которые действительно должны влиять на каждый процесс Zsh.

Убедитесь, что флаги шелла настроены корректно, файлы запуска не создают лишнего шума, и каждый генерируемый хук размещается там, где присутствуют все необходимые для него функции. Это делает конфигурацию переносимой между различными терминальными приложениями, без необходимости предполагать, что у macOS и Linux есть фиксированный режим запуска.

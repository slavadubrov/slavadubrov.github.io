DeepSeek mHC: Hyper-Connections с ограничением на многообразии

Viacheslav Dubrov

2026-01-21 · Обновлено 2026-07-15 · 8 мин · Инженерия моделей

Автоматический перевод Эта статья была автоматически переведена с оригинальной английской версии.

Современный deep learning опирается на residual connection. Hyper-Connections (HC) исследуют другое архитектурное измерение: расширяют residual state до нескольких взаимодействующих потоков. В статье DeepSeek о Manifold-Constrained Hyper-Connections (mHC) изучается, как сохранять стабильность такого роутинга при масштабировании обучения.

В этом материале сначала рассматриваются стандартные residual connections, затем добавляются Hyper-Connections и разбирается возникающая нестабильность. В конце описываются ограничение mHC и стоимость его реализации.

Коротко: HC заменяет одно residual state несколькими потоками и обучаемыми картами чтения, записи и смешивания. При последовательной композиции между слоями такие неограниченные карты могут усиливать или ослаблять сигналы. mHC приближённо проецирует residual mixing map на многогранник Биркгофа с помощью 20 итераций Sinkhorn-Knopp. В статье представлены эксперименты по масштабированию моделей 3B, 9B и 27B, а также дополнительные 6,7% времени обучения для четырёх потоков после оптимизации кастомных ядер и расписания (разделы 5.1 и 4.3).

Почему residual connections работают

Проблема глубины

Добавление слоёв может увеличить ёмкость модели, но одновременно усложняет оптимизацию и передачу сигналов. В зависимости от инициализации, нормализации и архитектуры forward-активации или backward-градиенты могут затухать, расти или становиться плохо обусловленными по мере увеличения глубины.

Решение через residual connection

В статье о ResNet было предложено простое исправление. Вместо обучения прямого отображения обучается residual, то есть отличие от identity:

Полезное свойство здесь — identity shortcut. Когда residual function F(x)F(x)F(x) выдаёт ноль, слой превращается в pass-through. Отсюда следуют два последствия:

  1. Прямой градиентный член: backpropagation включает путь через identity-компонент.
  2. Простое отображение по умолчанию: residual branch может оставаться близкой к нулю, если слою не требуется существенно менять state.

Это не устраняет все проблемы оптимизации, но сделало существенно более глубокие сети практически применимыми.

Как layer normalization меняет residual path

В Transformers появилась новая переменная: где размещать Layer Normalization (LN). Это решение кажется незначительным, но это не так.

ВариантРасположение LNПреимуществоОсновное ограничение
Post-LNПосле residual blockСильный вклад глубиныНа большой глубине может быть сложнее оптимизировать
Pre-LNПеред residual blockБолее прямой residual pathПредставления соседних слоёв могут становиться всё более похожими

Архитектура ResiDual объединяет residual paths Pre-LN и Post-LN. HC вместо этого расширяет residual state.

Hyper-Connections добавляют параллельные residual streams

Hyper-Connections (HC) увеличивают ширину residual stream, а не глубину модели.

Что такое stream

В стандартном Transformer каждый токен имеет state размерности ddd, который проходит через блоки. В начале сети HC копирует этот input embedding nnn раз, где nnn — это «коэффициент расширения», обычно равный 4. Скрытый state размерности ddd превращается в n×dn \times dn×d «гиперматрицу скрытых состояний».

В Hyper-Connections stream — это одна из nnn параллельных копий state.

Изначально копии идентичны, но затем расходятся, поскольку обучаемые карты считывают данные из потоков, записывают в них и смешивают их. В статье они интерпретируются как несколько паттернов соединений по глубине; при этом не предполагается, что каждый поток приобретёт фиксированную, понятную человеку роль.

Основные механизмы

Вместо одного residual pathway HC поддерживает nnn параллельных потоков, проходящих через всю сеть. На каждом transformer block выполняются три операции, каждая управляется небольшими обучаемыми весами:

  1. Read (Hpre\mathcal{H}^{pre}Hpre): агрегирует nnn потоков в вход размерности ddd, который получает attention- или feed-forward block.
  2. Write (Hpost\mathcal{H}^{post}Hpost): преобразует output блока в обновления для nnn потоков.
  3. Mix (Hres\mathcal{H}^{res}Hres): применяет n×nn \times nn×n residual map перед добавлением обновления блока.

Эти карты могут состоять из статических параметров и input-dependent terms. Residual map критична для стабильности, поскольку она многократно перемножается по глубине.

Что сообщает статья HC

В статье HC сообщается о сходимости в 1,8 раза быстрее для конфигурации OLMoE-1B-7B DHC×4 по сравнению с baseline, а также о приросте на downstream-задачах после 500B токенов (раздел 1). Это результат для одной протестированной конфигурации, а не общий коэффициент ускорения для четырёх потоков.

Проблема масштабирования

В статье mHC сообщается о нестабильности при масштабировании неограниченного HC до конфигурации 27B.

Почему неограниченный HC может стать нестабильным

Byte says

Во всех проверенных мной матрицах смешивания элементы были меньше единицы. Произведение по всем слоям — нет.

Те же неограниченные карты, которые делают HC гибким, одновременно убирают гарантированный identity path, благодаря которому residual connections легко обучать.

Проблема composite map

В стандартных residual connections:

xl+1=xl+F(xl)x_{l+1} = x_l + F(x_l)xl+1​=xl​+F(xl​)

Когда F(x)→0F(x) \rightarrow 0F(x)→0, это identity: xl+1=xlx_{l+1} = x_lxl+1​=xl​. Сигнал проходит без изменений.

В Hyper-Connections residual path включает матричное умножение:

xl+1=Hlres⋅xl+…x_{l+1} = \mathbf{H}^{res}_l \cdot x_l + \dotsxl+1​=Hlres​⋅xl​+…

После L слоёв сигнал становится равен:

xL=HLres×HL−1res×⋯×H1res×x0x_L = \mathbf{H}^{res}_L \times \mathbf{H}^{res}_{L-1} \times \dots \times \mathbf{H}^{res}_1 \times x_0xL​=HLres​×HL−1res​×⋯×H1res​×x0​

Поведение определяется composite matrix, а не тем, больше или меньше 1 отдельные элементы. Если последовательные карты имеют operator gain больше единицы вдоль согласованного направления, сигналы могут расти; gain меньше единицы может их ослаблять. Отрицательные элементы также могут вызывать взаимную компенсацию.

В статье mHC этот gain измеряется с помощью Amax Gain Magnitude: максимальной абсолютной суммы строк для forward propagation и суммы столбцов для backward propagation в composite residual map. В эксперименте с HC для модели 27B пиковое значение приближается к 3 000 и совпадает с нестабильным поведением обучения (раздел 5.4).

Таким образом, цель конструкции уже, чем принудительное превращение каждой карты в identity: нужно разрешить смешивание потоков, одновременно ограничив усиление при композиции карт.

Ограничение mHC

mHC сохраняет роутинг между потоками, но ограничивает каждую residual mixing matrix многогранником Биркгофа — множеством дважды стохастических матриц. Такая матрица имеет неотрицательные элементы, а сумма элементов в каждой строке и каждом столбце равна единице. Ограничение превращает каждый output stream в выпуклую комбинацию input streams и ограничивает spectral norm residual map единицей.

Что гарантирует дважды стохастическое свойство

Дважды стохастическое свойство одновременно даёт три преимущества:

ОграничениеСледствие
НеотрицательностьКаждый output является выпуклой комбинацией без компенсации знаков
Сумма строки = 1Постоянный сигнал во всех потоках сохраняется
Сумма столбца = 1Глобальное среднее по потокам сохраняется

Это не означает буквального сохранения евклидовой энергии. Дважды стохастическая карта может сглаживать различия между потоками. Она сохраняет среднее и обеспечивает нерасширяющий роутинг при указанной границе нормы.

У ограничения есть ещё три следствия:

  1. Spectral norm ≤ 1: residual routing map не может увеличивать евклидову норму.
  2. Замкнутость относительно умножения: произведение дважды стохастических матриц также является дважды стохастическим, поэтому ограничение сохраняется при композиции по глубине.
  3. Выпуклое смешивание: согласно теореме Биркгофа — фон Неймана, карта лежит в выпуклой оболочке матриц перестановок.

Проекция Sinkhorn-Knopp

Обучаемые residual logits не ограничены. Сначала mHC возводит их в экспоненту, чтобы получить положительную матрицу, а затем попеременно нормализует строки и столбцы. При достаточном числе итераций этот процесс Sinkhorn-Knopp приближается к дважды стохастической матрице; в статье используются 20 итераций как приближённая дифференцируемая проекция.

Для исходных logits AAA процедура выглядит так:

S = exp(A)
repeat 20 times:
    S = S / row_sum(S)
    S = S / column_sum(S)
return S

Операции дифференцируемы, но не бесплатны. mHC использует объединённое forward kernel и кастомное backward kernel, которое пересчитывает промежуточные состояния нормализации непосредственно на чипе.

Детали параметризации

  • Residual map: возведение в экспоненту и Sinkhorn-нормализация дают приближённо дважды стохастическую Hres\mathcal{H}^{res}Hres.
  • Read и write maps: Hpre=σ(H~pre)\mathcal{H}^{pre}=\sigma(\tilde{\mathcal{H}}^{pre})Hpre=σ(H~pre) и Hpost=2σ(H~post)\mathcal{H}^{post}=2\sigma(\tilde{\mathcal{H}}^{post})Hpost=2σ(H~post). Обе карты остаются неотрицательными, что уменьшает компенсацию коэффициентов разных знаков (раздел 4.2).

Полная архитектура mHC

Поток данных через каждый блок:

  1. Input: в слой входят nnn параллельных residual streams.
  2. Read (Hpre\mathcal{H}^{pre}Hpre): nnn потоков объединяются во вход, который получает функция слоя. В статье используется σ(H~pre)\sigma(\tilde{\mathcal{H}}^{pre})σ(H~pre), что делает коэффициенты неотрицательными.
  3. Computation: стандартный Transformer block (Attention или MLP) обрабатывает один агрегированный вектор.
  4. Write (Hpost\mathcal{H}^{post}Hpost): output блока преобразуется в обновления для nnn потоков с помощью 2σ(H~post)2\sigma(\tilde{\mathcal{H}}^{post})2σ(H~post). Коэффициенты остаются неотрицательными.
  5. Mix (Hres\mathcal{H}^{res}Hres): приближённо дважды стохастическая residual map смешивает входящие потоки перед добавлением обновления.
  6. Output: обновлённая матрица потоков передаётся на следующий слой.

Только residual mixing map использует проекцию Sinkhorn. Для read и write maps применяются неотрицательные параметризации. Это различие важно, поскольку гарантия композиции из статьи относится к Hres\mathcal{H}^{res}Hres.

Инфраструктура, необходимая для заявленных накладных расходов

Четыре потока увеличивают обращения к памяти для residual state, хранение активаций и обмен данными в пайплайне. Результат в 6,7% по времени зависит от следующей совместно спроектированной реализации.

Объединение ядер

Реализация объединяет операции с общим доступом к памяти, использует mixed precision там, где это уместно, и реализует большинство кастомных ядер с помощью TileLang. Цикл Sinkhorn и его кастомный backward pass выполняются внутри выделенных ядер, чтобы сократить трафик памяти и накладные расходы на запуск.

Выборочный пересчёт

Хранение каждого промежуточного состояния Sinkhorn для backpropagation привело бы к резкому росту потребления памяти. Поэтому mHC:

  • Освобождает промежуточные активации после forward pass.
  • Пересчитывает их на лету во время backward pass.

Расширенное расписание DualPipe перекрывает части коммуникаций, пересчёта и работы слоёв на границах pipeline. Достигнутый уровень перекрытия специфичен для этой training system.

Заявленный системный результат

В крупномасштабной конфигурации из статьи коэффициент расширения n=4n=4n=4 добавляет 6,7% времени обучения по сравнению с baseline (раздел 4.3). Это системный результат, а не накладные расходы обычной реализации во фреймворке.

Что показывают эксперименты

В сравнении для 27B неограниченный HC достигает пикового composite Amax Gain около 3 000. При 20-шаговой приближённой проекции Sinkhorn composite backward gain у mHC отклоняется от единицы, но остаётся ограниченным примерно значением 1,6 в представленном анализе (раздел 5.4).

Авторы также обучают варианты MoE размером 3B, 9B и 27B, вдохновлённые DeepSeek-V3 (раздел 5.3). На размере 27B mHC превосходит стандартный residual baseline на всех восьми заявленных downstream-бенчмарках и превосходит HC в шести из восьми (таблица 4). HC показывает немного лучший результат на GSM8K и MATH. Это внутренние эксперименты по претрейнингу, проведённые командой авторов, поэтому независимая репликация и сравнение на других архитектурах остаются открытыми вопросами.

Компромиссы и открытые вопросы

mHC не является безусловным улучшением для любой модели. Остаются четыре вопроса:

  1. Системные накладные расходы: 6,7% — это оптимизированный результат из статьи; другой рантайм, топология устройств или форма модели могут привести к иной стоимости.
  2. Сложность реализации: reference implementation позволяет выразить этот метод, но для достижения заявленного throughput нужны кастомные ядра, пересчёт и изменения расписания.
  3. Смещение при смешивании: дважды стохастическое свойство сохраняет среднее по потокам и предотвращает расширение через Hres\mathcal{H}^{res}Hres, но может сглаживать различия между потоками. Обновление блока при этом всё равно меняет общее представление.
  4. Область доказательств: наиболее сильные результаты получены на претрейнинге языковых моделей с архитектурами MoE, вдохновлёнными DeepSeek-V3. Обобщаемость на другие семейства моделей эта статья пока не подтверждает.

Главное

  1. Residual connections работают благодаря identity mapping — возможности передавать сигналы без изменений.
  2. Hyper-Connections масштабируют ширину, а не глубину, а в статье HC сообщается об ускоренной сходимости для одной конфигурации с четырьмя потоками.
  3. Неограниченный HC может утратить свойство сохранения residual path, когда residual maps компонуются по глубине.
  4. mHC ограничивает residual mixing многогранником Биркгофа, сохраняя среднее между потоками и ограничивая усиление.
  5. Sinkhorn-Knopp делает ограничение дифференцируемым, что позволяет обучать модель end-to-end.
  6. Заявленные 6,7% накладных расходов — достижение системной оптимизации, а не свойство одной только архитектуры.

mHC — перспективный подход к исследованию более широкой residual topology при сохранении хорошей обусловленности многократно применяемой residual map. Целесообразность его использования для другой модели зависит от независимого прироста качества и стоимости воспроизведения всего системного стека.

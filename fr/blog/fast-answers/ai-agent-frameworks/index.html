Meilleurs frameworks d’agents AI : LangGraph, CrewAI et OpenAI SDK

Viacheslav Dubrov

2026-06-08 · 5 min · Agents IA

Traduction automatique Cet article a été traduit automatiquement depuis la version originale en anglais.

Tous les frameworks d’agents fournissent une boucle permettant à un modèle de choisir et d’utiliser des outils. La différence utile réside dans ce que chaque framework gère autour de cette boucle : l’état, la recherche, les handoffs, le tracing ou le déploiement.

Choix par défaut : LangGraph pour un état explicite et un control flow durable. OpenAI Agents SDK pour un runtime Python compact et natif d’OpenAI. LlamaIndex lorsque la recherche constitue le produit. CrewAI uniquement lorsque le travail correspond à des rôles et à des handoffs. Microsoft Agent Framework pour les systèmes fortement basés sur Microsoft ou Azure. SmolAgents pour les petits agents code-first.

Comment choisir

Commencez par le control flow : comment l’agent passe d’une étape à l’autre et gère les échecs.

Si l’agent possède des états clairs, des retries, des approbations, des checkpoints et des exécutions reprenables, utilisez LangGraph. Vous écrirez davantage de structure au départ, mais cette structure constitue le système. LangGraph est le bon choix par défaut lorsque l’exécution peut dépasser une seule requête HTTP ou lorsque vous devez expliquer pourquoi l’agent a effectué une action.

Une fois le control flow établi, évaluez l’adéquation à la plateforme.

Si votre stack utilise déjà des modèles OpenAI et que vous voulez une API Python compacte, utilisez OpenAI Agents SDK. Vous obtenez les agents, les outils, les guardrails, les sessions et le tracing au même endroit. Il ne cherche pas à être un moteur de graphes générique, ce qui fait partie de son intérêt.

Examinez ensuite les données sur lesquelles l’agent travaille.

Si votre agent travaille principalement sur des documents, des index, la recherche et des moteurs de requêtes, commencez avec LlamaIndex. C’est généralement préférable à la construction d’une couche de recherche personnalisée autour de laquelle vous ajouteriez ensuite un framework d’agents. La plupart des agents documentaires échouent parce que la recherche et l’évaluation n’ont pas été suffisamment spécifiées, et non parce que la boucle était trop simple.

Enfin, n’utilisez les rôles que lorsqu’ils reflètent le workflow réel.

CrewAI est utile lorsque le processus réel comporte des rôles : chercheur, analyste, reviewer, rédacteur, opérateur. Il est moins pertinent lorsque vous inventez des rôles uniquement pour utiliser une abstraction multi-agent. Les noms ne remplacent pas la gestion de l’état.

Quand ne pas utiliser de framework d’agents

Ne commencez pas par un framework d’agents lorsqu’un workflow typé, un endpoint de recherche ou un moteur de règles suffit à résoudre le problème. Les agents sont utiles lorsque le système doit choisir l’étape suivante après avoir observé des résultats intermédiaires. Ils conviennent mal aux ETL fixes, aux approbations déterministes, aux workflows de facturation ou à tout problème dont toutes les branches sont connues à l’avance.

Ne construisez pas de système multi-agent avant qu’un agent ne fonctionne correctement. Répartir un workflow instable entre plusieurs agents ajoute des défaillances de coordination et de la latence.

Ne confondez pas l’observabilité du framework avec l’évaluation du produit. Les traces indiquent ce qui s’est passé. Les evals indiquent si le résultat était bon.

Mon parcours par défaut

  1. Construisez la première version sous la forme d’un agent unique doté d’outils ciblés.
  2. Ajoutez des traces et un petit dataset de régression avant d’ajouter une mémoire.
  3. Passez à LangGraph lorsque les transitions d’état deviennent une partie du produit.
  4. Utilisez OpenAI Agents SDK lorsque le produit est natif d’OpenAI et que la boucle doit rester compacte.
  5. Ajoutez des agents basés sur les rôles uniquement lorsque les responsabilités sont réellement séparables.

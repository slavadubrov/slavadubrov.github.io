Stable Diffusion sous macOS : Draw Things, DiffusionBee, ComfyUI, A1111 et Fooocus

L’exécution locale de modèles d’images sous macOS relève principalement d’une question d’outils. Draw Things, DiffusionBee, ComfyUI, AUTOMATIC1111 et Fooocus présentent des points communs, mais diffèrent en termes de configuration, de compatibilité des modèles, de contrôle du flux de travail, d’extensions et d’automatisation.

Une application de type glisser-déposer permet de démarrer rapidement ; un graphe de nœuds demande plus de temps à maîtriser, mais offre un accès plus complet au pipeline. Sur Apple Silicon, l’application, la famille de modèles, la précision, la taille de l’image ainsi que le flux de travail influencent tous la possibilité de générer une image. Choisissez l’interface en fonction du travail à réaliser, puis testez le modèle et les paramètres spécifiques.

En résumé. Utilisez Draw Things ou DiffusionBee lorsque l’application native suffit à l’usage. Préférez ComfyUI lorsque le graphe doit être examiné, partagé ou automatisé. Sélectionnez uniquement AUTOMATIC1111 pour des workflows dépendant de son interface ou de ses extensions. Considérez Fooocus comme un workflow adapté à l’époque de SDXL, et non comme une solution pour prendre en charge les modèles actuels : son projet officiel ne bénéficie que d’un soutien à long terme limité.

Un fichier de modèle n’est pas un workflow portable

Plusieurs applications peuvent charger des fichiers .safetensors, mais l’extension du fichier ne garantit pas pour autant la compatibilité. Un pipeline complet peut également nécessiter une architecture particulière, un encodeur de texte, un VAE, un planificateur, ControlNet, LoRA, un tokeniseur ou des paramètres spécifiques à l’application.

Il est essentiel de consigner l’ensemble des éléments ayant permis de générer l’image :

  • l’application et sa version ;
  • le répertoire du modèle, sa révision et sa licence ;
  • chaque composant et adaptateur du modèle ;
  • le prompt, le prompt négatif, la graine, le sampleur, le nombre d’étapes, les paramètres de guidance ainsi que les dimensions ;
  • le fichier de graphe ou de workflow, si l’application en fournit un.

Ces informations sont plus importantes que la popularité de l’application. Même avec la même graine, un changement dans le backend, le modèle, le sampleur ou la précision peut entraîner une image différente.

La mémoire unifiée est partagée, pas illimitée

Apple Silicon permet au CPU et à la GPU d’accéder au même pool de mémoire. Cela élimine les frontières entre copies distinctes, mais macOS et toutes les applications en cours d’exécution se disputent cette capacité.

Pour la génération d’images, l’utilisation maximale inclut bien plus que simplement les poids des checkpoints :

peak memory ≈ model components
            + intermediate activations
            + attention and runtime workspace
            + loaded adapters and control models
            + application and OS memory

La résolution, la taille des lots, l’architecture du modèle, la précision, le upscaling, ControlNet, ainsi que le fait que certains composants restent chargés influencent tous le résultat. Évitez d’acheter ou de choisir une machine en vous basant uniquement sur des spécifications telles que « 8/16/32 Go ». Testez le workflow prévu et surveillez la pression mémoire. Une génération qui ne fonctionne que grâce à un usage intensif du swap n’est pas un état de fonctionnement optimal.

Draw Things : interaction native et scriptage

Draw Things est une application pour plateforme Apple destinée à la génération d’images locales. Sa documentation actuelle couvre les modèles, les LoRAs, ControlNet, l’inversion textuelle, Core ML ainsi que le scriptage JavaScript versionné.

Choisissez-le lorsque le travail doit rester dans une application native tout en nécessitant un contrôle supérieur à celui offert par une simple boîte de prompts. Avant de l’adopter de manière standardisée, importez les composants du modèle exacts et reproduisez une modification, un adaptateur ou un flux de contrôle représentatif. Le terme « natif » décrit l’interface et l’implémentation ; il ne garantit pas la compatibilité ni la vitesse pour chaque nouvelle architecture.

DiffusionBee : flux de travail macOS emballé

DiffusionBee regroupe le téléchargement des modèles et les tâches de génération courantes dans une application de bureau. Sa documentation de projet liste la génération image vers image, l’inpainting, l’outpainting, ControlNet, LoRA, SDXL ainsi que le support partiel pour Flux.

Optez pour cette solution lorsque l’installation et une UI intégrée comptent plus que l’exportation d’un graphe de pipeline. Vérifiez la dernière version ainsi que l’architecture exacte avant de télécharger un modèle volumineux : une mention comme « support Flux » ne signifie pas que tous les dérivés, quantifications ou composants auxiliaires seront chargés.

ComfyUI : le flux de travail est un artefact

ComfyUI représente la génération sous forme de graphe de nœuds. Un workflow peut être stocké en JSON de manière indépendante de son résultat, ce qui permet d’examiner et de versionner le pipeline. Son exécuteur peut également éviter de recalculer les parties du graphe dont les entrées n’ont pas changé.

La version actuelle de ComfyUI Desktop prend en charge le Apple Silicon et gère son propre environnement, bien que la documentation officielle pour macOS la qualifie encore de bêta. Une installation via Homebrew est disponible :

brew install comfyui

Préférez ComfyUI lorsque votre pipeline comporte des branches, des composants réutilisables, plusieurs modèles ou nécessite une automatisation. Assurez-vous de conserver ensemble le fichier JSON, la version de l’application, les versions des nœuds principaux, les révisions des nœuds personnalisés ainsi que le manifeste des modèles.

Les nœuds personnalisés constituent des dépendances exécutables, et non de simples préférences inoffensives. Vérifiez leur code source, installez les scripts associés, fixez les versions à utiliser et isolez l’environnement d’exécution. Un graphe provenant d’un auteur inconnu peut faire référence à du code ou à des modèles que vous n’avez pas audités.

AUTOMATIC1111 : compatibilité avec une UI web éprouvée

AUTOMATIC1111 Stable Diffusion WebUI propose des paramètres de génération via une interface navigateur et prend en charge les scripts, les extensions ainsi qu’une API. Choisissez-le lorsque des tutoriels, des automatisations ou des extensions existantes font partie des exigences.

Son guide officiel pour Apple Silicon décrit les exceptions et les limites de performance, y compris une faible efficacité lors de l’entraînement. Avant d’adopter une configuration riche en extensions, vérifiez que la fonctionnalité requise fonctionne bien sur la version macOS et PyTorch ciblées.

Les extensions exécutent du code au sein de l’environnement de l’application. Fixez leurs versions, surveillez leurs mises à jour et maintenez le service en mode boucle locale, sauf si un accès distant est explicitement prévu et sécurisé.

Fooocus : une option limitée pour l’époque SDXL

Fooocus cache délibérément de nombreuses choix techniques derrière un flux de travail axé prioritairement sur les prompts. Cela peut s’avérer utile lorsque ses paramètres par défaut correspondent à la tâche à effectuer.

Le README actuel du projet indique que Fooocus est basé sur SDXL et bénéficie uniquement d’un soutien à court terme limité, se limitant aux correctifs de bugs. Il précise également que la version pour Mac n’a pas fait l’objet de tests approfondis et qualifie son installation sur Mac de non officielle. Par conséquent, Fooocus constitue un choix restreint pour ceux qui utilisent déjà ce flux de travail, et non une solution par défaut pour de nouvelles architectures ou des infrastructures macOS à long terme.

Exécuter un seul test d’acceptation représentatif

Utilisez un petit ensemble de tests d’acceptation avant de choisir un outil :

  1. Recréez un résultat de texte en image de base à partir d’une graine et de paramètres enregistrés.
  2. Exécutez l’opération la plus complexe requise : retraitement local, ControlNet, LoRA, agrandissement, ou un graphe à plusieurs étapes.
  3. Redémarrez l’application et reproduisez le workflow à partir des artefacts sauvegardés.
  4. Mesurez le temps de démarrage, le temps de génération, la pression mémoire maximale ainsi que les dimensions du résultat.
  5. Déplacez le workflow vers un compte utilisateur ou une machine propre et listez toutes les dépendances manquantes.
  6. Vérifiez les liens réseau locaux, les téléchargements, les paramètres d’analyse, les licences et l’origine des modèles.

Ne comparez pas des outils utilisant des points de contrôle, des résolutions, des nombres d’étapes ou des niveaux de précision différents en prétendant obtenir ainsi un benchmark de performance.

Une solution par défaut pratique

Pour des travaux exploratoires, commencez par une application native accompagnée d’un modèle dont elle fournit la documentation. Passez à ComfyUI lorsque le workflow lui-même devient précieux : lorsqu’il doit être revu, reproduit, automatisé ou transmis à quelqu’un d’autre. Préférez AUTOMATIC1111 ou Fooocus lorsque des dépendances existantes rendent leurs interfaces particulières utiles.

L’actif durable n’est pas une capture d’écran d’un bon résultat, mais plutôt le plus petit paquet reproductible contenant les identifiants du modèle, ses paramètres, ses dépendances ainsi que l’état du workflow, permettant de reproduire ce résultat.

Configuration du MacBook pour l’ingénierie en IA : outils macOS, Python, Docker et flux de travail terminal

Voici ma liste de contrôle pour transformer une installation neuve de macOS en station de travail d’ingénierie en IA : outils en ligne de commande, Homebrew, Python, Docker, paramètres par défaut du terminal et configuration des éditeurs.

En résumé : Homebrew, Python avec uv, Zsh fourni avec Oh My Zsh et Powerlevel10k, Docker, mes éditeurs et les outils d’IA locaux. Gardez les commandes et les fichiers dot dans le contrôle de version afin que la configuration soit reproductible.

1. Installer les outils de ligne de commande Xcode

xcode-select --install

Cela ouvre une boîte de dialogue qui vous guide tout au long de l’installation.

2. Installer Homebrew

Homebrew est le gestionnaire de paquets que j’utilise pour tout le reste de cette liste :

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

L’installateur explique ce qu’il va modifier et demande une confirmation. Sur Apple Silicon, Homebrew utilise /opt/homebrew par défaut. Suivez la commande brew shellenv affichée à la fin ; Homebrew n’ajoute pas lui-même brew à votre fichier de configuration shell PATH.

3. Installer les outils essentiels

brew install openssl readline sqlite3 xz zlib uv htop gitmoji pandoc ncdu tmux

Regroupés grossièrement selon leur fonction :

Environnement Python

Avant d’adopter uv, j’utilisais pyenv pour gérer mes environnements Python. uv couvre désormais ce workflow quotidien pour moi.

  • uv installe les versions de Python et gère les environnements de projet, les dépendances, les commandes et les fichiers de verrouillage.
  • pyenv est optionnel. Je l’utilise uniquement lorsque j’ai besoin d’un interpréteur compilé à partir des sources ou d’options de compilation personnalisées pour CPython que les distributions précompilées d’uv ne fournissent pas.

Installez pyenv séparément lorsque vous avez besoin de cette possibilité de compilation depuis les sources :

brew install pyenv

Librairies système

  • openssl fournit la prise en charge de la cryptographie SSL/TLS.
  • readline ajoute la modification de texte en ligne de commande.
  • sqlite3 est une base de données embarquée légère.
  • xz et zlib assurent la compression des données.

Outils de productivité

  • htop est un moniteur visuel du système et des processus.
  • tmux gère plusieurs sessions terminales.
  • ncdu analyse l’utilisation du disque de manière interactive.
  • gitmoji ajoute des emojis aux messages de commit.
  • pandoc convertit les documents entre différents formats.

Pour en savoir plus sur uv lui-même, consultez mon Guide rapide pour gérer Python sur macOS avec uv.

4. Choisir un terminal

Le terminal macOS par défaut est tout à fait convenable. J’ai utilisé iTerm2 pendant des années et je suis récemment passé à Warp, un terminal basé sur Rust doté de fonctionnalités d’IA intégrées. Le choix est personnel ; aucune des étapes ultérieures de configuration n’en dépend.

Optionnel : configuration d’iTerm2

Si vous restez avec iTerm2, voici deux paramètres que je modifie toujours :

Activer l’édition naturelle du texte

  1. Préférences → Profils → Touches → Mappage des touches
  2. Cliquez sur le menu déroulant Préréglages…
  3. Sélectionnez « Édition naturelle du texte »

Choisir un thème de couleur

  1. Parcourez les thèmes sur iTerm2-Color-Schemes
  2. Préférences → Profils → Couleurs → Préréglages de couleur…
  3. Cliquez sur Importer et sélectionnez le thème que vous avez téléchargé

5. Configurer Zsh

macOS inclut déjà Zsh et l’utilise comme shell de connexion par défaut. J’utilise la version fournie avec /bin/zsh ; installez Zsh de Homebrew uniquement si vous avez besoin d’une version plus récente issue de la branche principale.

Vérifiez la version de Zsh installée ainsi que votre shell de connexion actuel :

echo "$SHELL"
command -v zsh
zsh --version

Si Zsh est installé mais n’est pas sélectionné comme shell de connexion, passez à la version fournie avec le système :

chsh -s /bin/zsh

Ouvrez un nouveau terminal après avoir modifié le shell de connexion.

Oh My Zsh ajoute les paramètres par défaut et le système de plugins que j’utilise. Son installateur officiel est :

sh -c "$(curl -fsSL https://raw.githubusercontent.com/ohmyzsh/ohmyzsh/master/tools/install.sh)"

Le projet recommande d’examiner attentivement un installateur inconnu avant de l’exécuter. Il indique également qu’un fichier .zshrc existant est renommé en .zshrc.pre-oh-my-zsh lors de l’installation.

6. Ajouter des plugins pour Zsh

Modifiez votre ~/.zshrc pour charger ces plugins :

plugins=(
    aws bgnotify brew docker docker-compose
    emoji forklift gcloud git history iterm2
    keychain kubectl macos pre-commit
    pyenv pylint python screen themes
    tmux virtualenv vscode
    zsh-autosuggestions zsh-syntax-highlighting
)

Supprimez pyenv de la liste des plugins si vous avez sauté l’installation optionnelle de pyenv.

Les descriptions de tous ces plugins sont disponibles sur le wiki des plugins d’Oh My Zsh.

Les deux derniers nécessitent une installation séparée :

  • zsh-autosuggestions suggère des commandes tirées de votre historique au fur et à mesure que vous tapez.
  • zsh-syntax-highlighting met en couleur les commandes au fur et à mesure que vous tapez, ce qui facilite la détection des erreurs de frappe.

Suivez les instructions d’installation fournies sur chaque dépôt.

7. Personnaliser l’apparence avec Powerlevel10k

Powerlevel10k est le thème Zsh que j’utilise. Il affiche le répertoire de travail, l’état Git et l’environnement Python actif dans le prompt, et propose un assistant interactif pour ajuster l’apparence. Les instructions d’installation sont disponibles sur la page GitHub.

Polices dans d’autres éditeurs

Si vous utilisez VSCode ou un autre éditeur doté d’un terminal intégré, configurez la police du terminal afin que les icônes de Powerlevel10k s’affichent correctement :

  1. Ouvrez les paramètres de votre éditeur
  2. Recherchez terminal.integrated.fontFamily
  3. Réglez-le sur MesloLGS NF (installé en même temps que Powerlevel10k)

La configuration complète des polices est disponible dans le guide des polices de Powerlevel10k.

8. Éditeur et assistants IA

Je finis toujours par garder un IDE ouvert, avec un ou deux outils IA lancés à côté.

IDEs

  • Cursor — un fork de VSCode intégrant la programmation pair à base d’IA
  • VSCode — celui qui dispose d’un vaste catalogue d’extensions

Assistants IA

  • OpenAI Codex — l’agent de codage d’OpenAI
  • Claude — l’assistant d’Anthropic ; celui vers lequel je me tourne pour les tâches les plus complexes

De nos jours, cela revient à utiliser Cursor avec Codex et Claude Code en parallèle.

9. Le reste

Quelques éléments supplémentaires que j’installe sur chaque machine :

  • GitHub Desktop — client Git visuel lorsque je ne souhaite pas passer par la ligne de commande
  • Docker Desktop — le runtime de conteneurs que j’utilise ; Podman Desktop en est une alternative
  • Ollama ou LM Studio — exécutez des LLM localement sur le Mac

10. Voilà la configuration

Tout ce qui précède s’installe sur chaque nouveau MacBook avant que je ne commence à travailler réellement. À adapter selon vos préférences.

Points clés

  1. Il s’agit d’une configuration personnelle, et non d’une base minimale ou universelle pour macOS. Supprimez tout ce que vous n’utilisez pas.
  2. Le /bin/zsh fourni est suffisant pour cette configuration. Installez Zsh via Homebrew uniquement lorsque vous avez besoin d’une version plus récente issue de l’upstream.
  3. Désormais, uv gère l’installation de Python et les environnements de projet dans mon flux de travail quotidien. pyenv reste optionnel pour les interprètes CPython compilés à partir des sources ou personnalisés.
  4. Gardez les commandes d’installation, les fichiers dotfiles sans secrets, les extensions d’éditeur et les emplacements des modèles documentés afin que la prochaine configuration soit automatisée.

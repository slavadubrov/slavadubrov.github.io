Stable Diffusion unter macOS: Lokale Bild-Tools im Vergleich

Viacheslav Dubrov

2025-05-10 · Aktualisiert 2026-07-15 · 6 Min. · Entwicklungswerkzeuge

Automatische Übersetzung Dieser Artikel wurde automatisch aus der englischen Originalversion übersetzt.

Die lokale Ausführung von Bild-Models unter macOS ist vor allem eine Frage des Toolings. Draw Things, DiffusionBee, ComfyUI, AUTOMATIC1111 und Fooocus überschneiden sich, unterscheiden sich aber bei Einrichtung, Model-Unterstützung, Workflow-Kontrolle, Erweiterungen und Automatisierung.

Eine Drag-and-drop-App ermöglicht einen schnellen Einstieg; ein Node Graph erfordert mehr Einarbeitung, macht dafür aber mehr Teile der Pipeline sichtbar. Auf Apple Silicon beeinflussen Anwendung, Model-Familie, Precision, Bildgröße und Workflow gemeinsam, ob die Generierung in den verfügbaren Speicher passt. Wähle das Interface nach der Arbeit aus, die du reproduzieren musst, und teste anschließend das exakte Model mit den exakten Einstellungen.

TL;DR. Starte mit Draw Things oder DiffusionBee, wenn eine native Anwendung die Aufgabe abdeckt. Verwende ComfyUI, wenn der Graph selbst inspiziert, geteilt oder automatisiert werden muss. Wähle AUTOMATIC1111 nur für einen Workflow, der von dessen Interface oder Erweiterungen abhängt. Betrachte Fooocus als stabilen Workflow aus der SDXL-Ära und nicht als Weg zu aktueller Model-Unterstützung: Das offizielle Projekt befindet sich in einer eingeschränkten langfristigen Wartungsphase.

Eine Model-Datei ist kein portabler Workflow

Mehrere Anwendungen können .safetensors-Dateien laden, aber eine übereinstimmende Dateiendung bedeutet nicht, dass das Model funktioniert. Eine vollständige Pipeline kann außerdem eine bestimmte Architektur, einen Text Encoder, VAE, Scheduler, ControlNet, LoRA, Tokenizer oder eine anwendungsspezifische Konfiguration erfordern.

Halte alles fest, was ein Bild erzeugt hat:

  • Anwendung und Version
  • Model-Repository, Revision und Lizenz
  • jede Model-Komponente und jedes Adapter
  • Prompt, negativer Prompt, Seed, Sampler, Steps, Guidance und Dimensionen
  • Graph- oder Workflow-Datei, wenn die Anwendung eine solche bereitstellt

Diese Dokumentation ist wichtiger als die Popularität der App. Derselbe Seed kann nach einer Änderung an Backend, Model, Sampler oder Precision trotzdem ein anderes Bild erzeugen.

Unified Memory wird gemeinsam genutzt, ist aber nicht unbegrenzt

Apple Silicon ermöglicht es CPU und GPU, auf einen gemeinsamen Speicherpool zuzugreifen. Dadurch entfällt eine separate Kopiergrenze, aber macOS und jede geöffnete Anwendung konkurrieren um dieselbe Kapazität.

Bei der Bildgenerierung umfasst der Spitzenverbrauch mehr als nur Checkpoint Weights:

peak memory ≈ model components
            + intermediate activations
            + attention and runtime workspace
            + loaded adapters and control models
            + application and OS memory

Auflösung, Batch-Größe, Model-Architektur, Precision, Upscaling, ControlNet und die Frage, ob Komponenten geladen bleiben, verändern das Ergebnis. Kaufe oder wähle keine Maschine anhand einer universellen Tabelle mit „8/16/32 GB“. Teste den vorgesehenen Workflow und beobachte den Memory Pressure. Eine Generierung, die nur durch dauerhaftes Swapping gelingt, ist kein komfortabler Betriebspunkt.

Die Tabelle ist kein Ranking. Sie zeigt, wo der Workflow-Zustand liegt: innerhalb einer App, verteilt über ein Formular oder in einem überprüfbaren Graph.

Draw Things: native Interaktion und Scripting

Draw Things ist eine Anwendung für Apple-Plattformen zur lokalen Bildgenerierung. Die aktuelle Dokumentation deckt Models, LoRAs, ControlNet, textual inversion, Core ML und versioniertes JavaScript-Scripting ab.

Wähle es, wenn die Arbeit in einer nativen Anwendung bleiben soll, aber mehr Kontrolle als ein Prompt-Feld erfordert. Bevor du es standardisierst, importiere die exakten Model-Komponenten und reproduziere eine repräsentative Bearbeitung, ein Adapter- oder ein Control-Workflow. „Native“ beschreibt Interface und Implementierung; es garantiert weder Unterstützung noch Geschwindigkeit für jede neue Architektur.

DiffusionBee: paketierter macOS-Workflow

DiffusionBee bündelt den Model-Download und gängige Generierungsaufgaben in einer Desktop-Anwendung. Die Projektdokumentation nennt Image-to-Image, Inpainting, Outpainting, ControlNet, LoRA und SDXL. Die DiffusionBee-Release-Notes zu Version 2.5.3 melden Flux.1-Unterstützung ausschließlich auf arm64-Macs mit macOS 13 oder neuer.

Wähle es, wenn eine einfache Installation und ein integriertes UI wichtiger sind als der Export eines Pipeline-Graphs. Prüfe vor dem Download eines großen Models das neueste Release und die exakte Architektur. Ein Feature-Hinweis wie „Flux-Unterstützung“ bedeutet nicht, dass jedes Derivat, jede Quantization oder jede zusätzliche Komponente geladen werden kann.

ComfyUI: Der Workflow ist ein Artefakt

ComfyUI stellt Generierung als Node Graph dar. Ein Workflow kann unabhängig von seinem Output als JSON gespeichert werden, wodurch die Pipeline inspizierbar und versionierbar wird. Der Executor kann außerdem Graph-Abschnitte überspringen, deren Inputs sich nicht geändert haben.

Der aktuelle ComfyUI-Desktop-Build unterstützt Apple Silicon und verwaltet seine eigene Umgebung, obwohl die offizielle macOS-Dokumentation Desktop weiterhin als Beta bezeichnet. Eine Homebrew-Installation ist verfügbar:

brew install comfyui

Wähle ComfyUI, wenn eine Pipeline Verzweigungen, wiederverwendbare Komponenten, mehrere Models oder Automatisierung umfasst. Bewahre JSON, Anwendungsversion, Versionen der Core Nodes, Revisionen der Custom Nodes und das Model-Manifest gemeinsam auf.

Custom Nodes sind ausführbare Abhängigkeiten. Prüfe ihren Quellcode und ihre Installationsskripte, pinne Revisionen und isoliere die Umgebung. Ein Graph eines unbekannten Autors kann auf Code und Models verweisen, die du nicht auditiert hast.

AUTOMATIC1111: Kompatibilität mit einer etablierten Web UI

AUTOMATIC1111 Stable Diffusion WebUI stellt Generierungseinstellungen über ein Browser-Interface bereit und unterstützt Scripts, Erweiterungen und eine API. Wähle es, wenn ein bestimmtes Tutorial, eine Automatisierung oder eine Erweiterung bereits Teil der Anforderungen ist.

Die offizielle Anleitung für Apple Silicon dokumentiert Ausnahmen und Performance-Einschränkungen, darunter schwache Trainings-Performance. Bestätige vor der Einführung eines erweiterungsintensiven Setups, dass das benötigte Feature mit den Zielversionen von macOS und PyTorch funktioniert.

Erweiterungen führen Code innerhalb der Anwendungsumgebung aus. Pinne sie, prüfe Updates und lasse den Service auf Loopback laufen, sofern Remote-Zugriff nicht bewusst eingerichtet und geschützt wird.

Fooocus: Eine begrenzte Option aus der SDXL-Ära

Fooocus verbirgt bewusst viele technische Entscheidungen hinter einem meinungsstarken Prompt-first-Workflow. Das kann nützlich sein, wenn seine Defaults zur Aufgabe passen.

Die aktuelle README des Projekts besagt, dass Fooocus auf SDXL ausgerichtet ist und sich mit ausschließlich Bugfixes in einer eingeschränkten langfristigen Wartungsphase befindet. Außerdem wird darauf hingewiesen, dass Mac nicht intensiv getestet wird und die Mac-Installation inoffiziell ist. Damit ist Fooocus eine begrenzte Wahl für einen bestehenden Fooocus-Workflow, aber nicht der Standardweg für neue Architekturen oder für ein macOS-Setup, das du langfristig warten möchtest.

Führe einen repräsentativen Acceptance Test aus

Verwende einen kleinen Acceptance Set, bevor du dich für ein Tool entscheidest:

  1. Reproduziere ein Text-to-Image-Basisergebnis mit dokumentiertem Seed und dokumentierten Einstellungen.
  2. Führe die anspruchsvollste benötigte Operation aus: Inpainting, ControlNet, LoRA, Upscale oder einen mehrstufigen Graph.
  3. Starte die Anwendung neu und reproduziere den Workflow aus gespeicherten Artefakten.
  4. Miss Cold Start, Generierungszeit, maximalen Memory Pressure und Output-Dimensionen.
  5. Verschiebe den Workflow in ein sauberes Benutzerkonto oder auf eine andere Maschine und liste jede fehlende Abhängigkeit auf.
  6. Prüfe Bindings im lokalen Netzwerk, Downloads, Analytics-Einstellungen, Lizenzen und die Herkunft der Models.

Vergleiche Tools nicht mit unterschiedlichen Checkpoints, Auflösungen, Step-Anzahlen oder Precision-Einstellungen und bezeichne das Ergebnis anschließend als Runtime-Benchmark.

Eine praktische Standardeinstellung

Starte bei explorativer Arbeit mit einer nativen App und einem Model, das sie dokumentiert. Wechsle zu ComfyUI, sobald der Workflow selbst wertvoll wird: wenn er überprüft, wiederholt, automatisiert oder an andere Personen übergeben werden muss. Behalte AUTOMATIC1111 oder Fooocus, wenn eine bestehende Abhängigkeit ihre spezifische Oberfläche nützlich macht.

Erhaltenswert ist das kleinste reproduzierbare Paket aus Model-Identitäten, Parametern, Abhängigkeiten und Workflow-Zustand, mit dem sich das Ergebnis erneut erzeugen lässt.

Stable Diffusion unter macOS: Draw Things, DiffusionBee, ComfyUI, AUTOMATIC1111 und Fooocus

Die lokale Ausführung von Bildmodellen unter macOS ist in erster Linie eine Frage der gewählten Werkzeuge. Draw Things, DiffusionBee, ComfyUI sowie AUTOMATIC1111 und Fooocus überschneiden sich teilweise, weisen jedoch Unterschiede hinsichtlich der Einrichtung, der unterstützten Modelle, der Kontrolle des Arbeitsablaufs, der Erweiterungen sowie der Automatisierung auf.

Eine App mit Drag‑and‑Drop-Funktionalität ermöglicht einen schnellen Einstieg; ein Knotengraph hingegen erfordert mehr Lernzeit, bietet aber einen umfassenderen Überblick über den gesamten Pipeline-Ablauf. Auf Apple Silicon beeinflussen die Anwendung, die Modellfamilie, die Präzision, die Bildgröße sowie der Arbeitsablauf maßgeblich, ob eine Generierung möglich ist. Wählen Sie die für Ihre Aufgabe geeignete Benutzeroberfläche aus und prüfen Sie anschließend das konkrete Modell sowie die Einstellungen.

Kurzfassung: Verwenden Sie bei Aufgaben, die bereits durch eine native Anwendung abgedeckt werden, Draw Things oder DiffusionBee. Nutzen Sie ComfyUI, wenn der Knotengraph selbst untersucht, geteilt oder automatisiert werden muss. Wählen Sie AUTOMATIC1111 ausschließlich dann, wenn Ihr Arbeitsablauf auf seiner Benutzeroberfläche oder seinen Erweiterungen beruht. Betrachten Sie Fooocus als Workflow für die SDXL-Ära – es bietet keine Unterstützung für aktuelle Modelle; das offizielle Projekt erhält nur begrenzte Langzeitunterstützung.

Ein Modellfile ist kein portabler Arbeitsablauf

Mehrere Anwendungen können .safetensors-Dateien laden, doch allein eine passende Endung garantiert keine Kompatibilität. Ein vollständiger Pipeline kann zudem eine bestimmte Architektur, einen Textencoder, eine VAE, einen Scheduler, ControlNet, LoRA, einen Tokenizer oder anwendungsspezifische Konfigurationen erfordern.

Erhalten Sie eine detaillierte Dokumentation der Komponenten, aus denen ein Bild entstanden ist:

  • Anwendung und Version
  • Modellrepository, Revision und Lizenz
  • Jedes einzelne Modulkomponente sowie Adapter
  • Prompt, Negative Prompt, Seed, Sampler, Anzahl der Schritte, Guidance‑Parameter sowie Bilddimensionen
  • Graph- oder Workflow‑Datei, sofern die Anwendung diese bereitstellt

Diese Dokumentation ist wichtiger als die Beliebtheit der Anwendung. Selbst mit demselben Seed kann nach Änderungen am Backend, Modell, Sampler oder der Präzision ein anderes Bild entstehen.

Gemeinsame Speicherressourcen sind begrenzt, nicht unbegrenzt

Apple Silicon ermöglicht es CPU und GPU, auf denselben Speicherpool zuzugreifen. Dadurch entfällt eine separate Kopiergrenze, doch macOS sowie alle laufenden Anwendungen konkurrieren um dieselbe Kapazität.

Bei der Bildgenerierung umfasst der maximale Speicherverbrauch mehr als nur die Gewichte der Checkpoints:

peak memory ≈ model components
            + intermediate activations
            + attention and runtime workspace
            + loaded adapters and control models
            + application and OS memory

Auflösung, Batch‑Größe, Modellarchitektur, Präzision, Upscaling, ControlNet sowie die Frage, ob bestimmte Komponenten weiterhin geladen bleiben, beeinflussen das Ergebnis. Kaufen oder wählen Sie keine Maschine aufgrund einer pauschalen Angabe wie „8/16/32 GB“. Testen Sie den gewünschten Arbeitsablauf und beobachten Sie den Speicherdruck. Eine Generierung, die nur durch kontinuierliches Swapping funktioniert, stellt keinen stabilen Betriebspunkt dar.

Draw Things: native Interaktion und Scripting

Draw Things ist eine Apple‑Plattform‑Anwendung zur lokalen Bildgenerierung. Die aktuelle Dokumentation behandelt Modelle, LoRAs, ControlNet, textuelle Inversion, Core ML sowie versionierte JavaScript‑Skripte.

Wählen Sie dieses Tool, wenn die Arbeit innerhalb einer nativen Anwendung bleiben soll, aber dennoch mehr Kontrolle als eine Prompt‑Box erforderlich ist. Bevor Sie sich darauf festlegen, importieren Sie die genauen Modulkomponenten und führen Sie eine repräsentative Bearbeitung, einen Adapter oder einen Steuerungsworkflow durch. „Nativ“ beschreibt die Benutzeroberfläche und Implementierung; es garantiert jedoch keine Unterstützung oder Geschwindigkeit für jede neue Architektur.

DiffusionBee: paketierter macOS‑Workflow

DiffusionBee bündelt das Herunterladen von Modellen sowie gängige Generierungsaufgaben in einer Desktop‑Anwendung. Die Projektdokumentation listet Bild-zu-Bild‑Verarbeitung, Inpainting, Outpainting, ControlNet, LoRA, SDXL sowie ausgewählte Flux‑Unterstützung auf.

Wählen Sie dieses Tool, wenn Installation und eine integrierte Benutzeroberfläche wichtiger sind als das Exportieren eines Pipeline‑Graphen. Prüfen Sie vor dem Herunterladen eines großen Modells die neueste Version sowie die genaue Architektur: Ein Funktionslabel wie „Flux‑Unterstützung“ bedeutet nicht, dass alle Ableitungen, Quantisierungen oder Hilfskomponenten geladen werden.

ComfyUI: Der Workflow ist ein Artefakt

ComfyUI stellt die Generierung als Knotengraph dar. Ein Workflow kann unabhängig von seinem Ausgang als JSON gespeichert werden, wodurch der Pipeline‑Ablauf überprüfbar und versionierbar ist. Der Executor kann außerdem darauf verzichten, Graphabschnitte neu zu berechnen, deren Eingaben sich nicht geändert haben.

Die aktuelle ComfyUI Desktop‑Version unterstützt Apple Silicon und verwalten ihr eigenes Umfeld, obwohl die offizielle macOS‑Dokumentation sie weiterhin als Beta bezeichnet. Eine Installation über Homebrew ist ebenfalls möglich:

brew install comfyui

Wählen Sie ComfyUI, wenn ein Pipeline mehrere Pfade, wiederverwendbare Komponenten, mehrere Modelle oder Automatisierungsmechanismen aufweist. Bewahren Sie dabei JSON‑Dateien, die Anwendungsversion, die Versionen der Core‑Nodes, die Revisionen der Custom‑Nodes sowie das Modellmanifest zusammen auf.

Custom‑Nodes sind ausführbare Abhängigkeiten und keine harmlosen Vorlagen. Prüfen Sie deren Quellcode, installieren Sie die dazugehörigen Skripte, fixieren Sie die Revisionen und isolieren Sie die Umgebung. Ein Graph von einem unbekannten Entwickler kann auf Code und Modelle verweisen, die Sie noch nicht überprüft haben.

AUTOMATIC1111: Kompatibilität mit einer etablierten Web‑UI

AUTOMATIC1111 Stable Diffusion WebUI stellt die Erstellungs-Einstellungen über eine Browseroberfläche bereit und unterstützt Skripte, Erweiterungen sowie eine API. Wählen Sie diese Lösung, wenn bereits vorhandene Tutorials, Automatisierungen oder Erweiterungen Teil der Anforderungen sind.

Die offizielle Anleitung für Apple Silicon dokumentiert Ausnahmen sowie Leistungseinschränkungen, darunter eine schwache Trainingsleistung. Stellen Sie vor dem Einsatz einer erweiterungsreichen Konfiguration sicher, dass die gewünschten Funktionen unter den jeweiligen macOS‑ und PyTorch‑Versionen funktionieren.

Erweiterungen führen Code innerhalb der Anwendungsumgebung aus. Fixieren Sie sie, prüfen Sie regelmäßig Updates und halten Sie den Dienst im Loopback‑Modus, es sei denn, ein Remote-Zugriff ist beabsichtigt und entsprechend geschützt.

Fooocus: Eine eingeschränkte Option aus der SDXL‑Ära

Fooocus verbirgt bewusst viele technische Entscheidungen hinter einem auf Prompten ausgerichteten Workflow. Dies kann nützlich sein, wenn die Standardeinstellungen zur Aufgabenlösung passen.

In der aktuellen README des Projekts heißt es, Fooocus basiere auf SDXL und erhalte nur begrenzte langfristige Unterstützung in Form von Fehlerbehebungen. Zudem wird angegeben, dass Mac‑Systeme nicht intensiv getestet wurden und die Mac‑Installation als inoffiziell gilt. Daher eignet sich Fooocus lediglich für bestehende Fooocus‑Workflows und nicht als Standardlösung für neue Architekturen oder langfristig genutzte macOS‑Infrastrukturen.

Ausführen eines repräsentativen Akzeptanztests

Bevor Sie sich für ein Tool entscheiden, führen Sie zunächst einen kleinen Akzeptanztest durch:

  1. Erstellen Sie ein Basistext-zu-Bild-Ergebnis mithilfe einer gespeicherten Seed‑Wertung und der entsprechenden Einstellungen.
  2. Führen Sie die schwierigste erforderliche Operation aus: Inpainting, ControlNet, LoRA, Upscaling oder einen mehrstufigen Graphen.
  3. Starten Sie die Anwendung erneut und wiederholen Sie den Workflow anhand der gespeicherten Artefakte.
  4. Messen Sie den Cold‑Start‑Zeitpunkt, die Generierungszeit, den maximalen Speicherbedarf sowie die Ausgabemessungen.
  5. Übertragen Sie den Workflow auf ein sauberes Benutzerkonto oder eine andere Maschine und listen Sie alle fehlenden Abhängigkeiten auf.
  6. Überprüfen Sie die Bindung im lokalen Netzwerk, Downloads, Analyseteinstellungen, Lizenzen sowie die Herkunft der Modelle.

Vergleichen Sie keine Tools mit unterschiedlichen Checkpoints, Auflösungen, Anzahl der Schritte oder Präzisionsgraden und bezeichnen Sie das Ergebnis nicht als Laufzeit‑Benchmark.

Eine praktische Standardlösung

Für exploratives Arbeiten sollten Sie zunächst eine native App sowie ein von ihr dokumentiertes Modell verwenden. Wechseln Sie zu ComfyUI, sobald der Workflow selbst an Wert gewinnt – beispielsweise dann, wenn er überprüft, wiederholt, automatisiert oder an Dritte weitergegeben werden muss. Verwenden Sie weiterhin AUTOMATIC1111 oder Fooocus, wenn bestehende Abhängigkeiten deren spezifische Funktionalitäten nützlich machen.

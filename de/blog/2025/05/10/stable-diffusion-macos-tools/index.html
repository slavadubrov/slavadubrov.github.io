Stable Diffusion auf macOS: Lokale Bild-Tools im Vergleich

Viacheslav Dubrov

2025-05-10 · Aktualisiert 2026-07-15 · 6 Min. · Entwicklungswerkzeuge

Automatische Übersetzung Dieser Artikel wurde automatisch aus der englischen Originalversion übersetzt.

Bild-Models lokal auf macOS auszuführen, ist vor allem eine Frage des Toolings. Draw Things, DiffusionBee, ComfyUI, AUTOMATIC1111 und Fooocus überschneiden sich, unterscheiden sich jedoch bei Einrichtung, Model-Unterstützung, Workflow-Kontrolle, Erweiterungen und Automatisierung.

Mit einer Drag-and-drop-App gelingt der Einstieg schnell; ein Node Graph benötigt mehr Einarbeitungszeit, macht dafür aber mehr Teile der Pipeline sichtbar. Auf Apple Silicon beeinflussen die Anwendung, die Model-Familie, die Precision, die Bildgröße und der Workflow, ob die Generierung in den verfügbaren Speicher passt. Wählen Sie das Interface anhand der Aufgaben, die Sie reproduzieren müssen, und testen Sie anschließend das exakte Model mit den exakten Einstellungen.

TL;DR. Starten Sie mit Draw Things oder DiffusionBee, wenn eine native Anwendung die Aufgabe abdeckt. Verwenden Sie ComfyUI, wenn der Graph selbst überprüft, geteilt oder automatisiert werden muss. Wählen Sie AUTOMATIC1111 nur für einen Workflow, der von dessen Interface oder Erweiterungen abhängt. Betrachten Sie Fooocus als stabilen Workflow aus der SDXL-Ära, nicht als Weg zu aktueller Model-Unterstützung: Das offizielle Projekt befindet sich in einer eingeschränkten Long-Term-Support-Phase.

Eine Model-Datei ist kein portabler Workflow

Mehrere Anwendungen können .safetensors-Dateien laden, aber eine übereinstimmende Dateiendung bedeutet nicht, dass das Model funktioniert. Eine vollständige Pipeline kann außerdem eine bestimmte Architektur, einen Text Encoder, eine VAE, einen Scheduler, ControlNet, LoRA, einen Tokenizer oder eine anwendungsspezifische Konfiguration erfordern.

Dokumentieren Sie alles, was ein Bild erzeugt hat:

  • Anwendung und Version
  • Model-Repository, Revision und Lizenz
  • jede Model-Komponente und jeden Adapter
  • Prompt, negativen Prompt, Seed, Sampler, Steps, Guidance und Dimensionen
  • Graph- oder Workflow-Datei, sofern die Anwendung eine solche bereitstellt

Diese Aufzeichnung ist wichtiger als die Popularität der Anwendung. Derselbe Seed kann nach einer Änderung an Backend, Model, Sampler oder Precision dennoch ein anderes Bild erzeugen.

Unified Memory wird geteilt, ist aber nicht unbegrenzt

Apple dokumentiert, dass seine GPUs ein Unified-Memory-Modell verwenden, bei dem CPU und GPU den Systemspeicher gemeinsam nutzen, obwohl der Ressourcenzugriff weiterhin vom Metal Storage Mode abhängt. Dadurch entfällt eine separate Kopiergrenze. macOS und jede geöffnete Anwendung verwenden jedoch dieselbe physische Kapazität; der Aktivitätsmonitor zeigt die Nutzung durch Apps, Wired Memory, komprimierten Speicher und Swap.

Verwenden Sie dies bei der Bildgenerierung als konzeptionelle Aufstellung des maximalen Speicherbedarfs, nicht als Formel zur Dimensionierung:

peak memory ≈ model components
            + intermediate activations
            + attention and runtime workspace
            + loaded adapters and control models
            + application and OS memory

Auflösung, Batch-Größe, Model-Architektur, Precision, Upscaling, ControlNet und die Frage, ob Komponenten geladen bleiben, verändern das Ergebnis. Keine Apple-Quelle macht aus dieser Aufstellung eine universelle Regel wie „8/16/32 GB“. Die Auswahl eines Rechners anhand dieser Werte ist daher eine aus Workflow-Tests abgeleitete Entscheidung. Testen Sie den vorgesehenen Workflow und beobachten Sie anschließend Memory Pressure und Swap Used. Anhaltendes Swapping ist ein Hinweis darauf, die Arbeitslast zu reduzieren oder mehr Speicher zu wählen.

Draw Things: native Interaktion und Scripting

Draw Things ist eine Anwendung für Apple-Plattformen zur lokalen Bildgenerierung. Die aktuelle Dokumentation behandelt Models, LoRAs, ControlNet, Textual Inversion, Core ML und versioniertes JavaScript-Scripting.

Wählen Sie das Tool, wenn die Arbeit in einer nativen Anwendung bleiben, aber mehr Kontrolle als in einem Prompt-Feld erfordern soll. Importieren Sie vor einer Standardisierung die exakten Model-Komponenten und reproduzieren Sie eine repräsentative Bearbeitung, einen Adapter oder einen Control-Workflow. „Native“ beschreibt Interface und Implementierung; es garantiert weder Unterstützung noch Geschwindigkeit für jede neue Architektur.

DiffusionBee: paketierter macOS-Workflow

DiffusionBee bündelt den Model-Download und gängige Generierungsaufgaben in einer Desktop-Anwendung. Die Projektdokumentation nennt Image-to-Image, Inpainting, Outpainting, ControlNet, LoRA und SDXL. Die DiffusionBee-Release-Notes zu Version 2.5.3 berichten von Flux.1-Unterstützung ausschließlich auf arm64-Macs mit macOS 13 oder neuer.

Wählen Sie das Tool, wenn eine einfache Installation und ein integriertes UI wichtiger sind als der Export eines Pipeline-Graphen. Prüfen Sie vor dem Download eines großen Models das aktuelle Release und die exakte Architektur. Ein Feature-Label wie „Flux-Unterstützung“ bedeutet nicht, dass jedes Derivat, jede Quantization oder jede zusätzliche Komponente geladen werden kann.

ComfyUI: Der Workflow ist ein Artefakt

ComfyUI stellt die Generierung als Node Graph dar. Ein Workflow kann unabhängig von seinem Output als JSON gespeichert werden, wodurch die Pipeline inspizierbar und versionierbar wird. Sein Executor kann außerdem Graph-Abschnitte überspringen, deren Inputs sich nicht geändert haben.

Comfy Desktop ist ein Multi-Installation-Manager für lokale ComfyUI-Instanzen. Die aktuelle macOS-Dokumentation unterstützt Apple Silicon ab macOS 13 und installiert aus einer heruntergeladenen .dmg. Wenn Sie Homebrew bevorzugen, lautet das aktuelle Cask comfy (nicht comfyui):

brew install --cask comfy

Wählen Sie ComfyUI, wenn eine Pipeline Branches, wiederverwendbare Komponenten, mehrere Models oder Automatisierung umfasst. Bewahren Sie JSON, Anwendungsversion, Versionen der Core Nodes, Revisionen der Custom Nodes und das Model-Manifest gemeinsam auf.

Custom Nodes sind ausführbare Dependencies. Prüfen Sie deren Quellcode und Installationsskripte, pinnen Sie Revisionen und isolieren Sie die Umgebung. Ein Graph eines unbekannten Autors kann auf Code und Models verweisen, die Sie nicht auditiert haben.

AUTOMATIC1111: Kompatibilität mit einer etablierten Web UI

AUTOMATIC1111 Stable Diffusion WebUI stellt Generierungseinstellungen über ein Browser-Interface bereit und unterstützt Scripts, Erweiterungen und eine API. Wählen Sie es, wenn ein bestimmtes Tutorial, eine Automatisierung oder eine Erweiterung bereits Teil der Anforderung ist.

Der offizielle Apple-Silicon-Leitfaden dokumentiert Ausnahmen und Performance-Einschränkungen, darunter eine schwache Trainings-Performance. Prüfen Sie vor der Einführung eines erweiterungsintensiven Setups, ob das erforderliche Feature mit den Zielversionen von macOS und PyTorch funktioniert.

Erweiterungen führen Code innerhalb der Anwendungsumgebung aus. Pinnen Sie sie, prüfen Sie Updates und lassen Sie den Service nur an Loopback gebunden, sofern Remote-Zugriff nicht bewusst eingerichtet und geschützt ist.

Fooocus: eine begrenzte Option aus der SDXL-Ära

Fooocus verbirgt bewusst viele technische Entscheidungen hinter einem opinionated, Prompt-first Workflow. Das kann nützlich sein, wenn seine Defaults zur Aufgabe passen.

Das aktuelle README des Projekts besagt, dass Fooocus auf SDXL ausgerichtet ist und sich in einem eingeschränkten Long-Term-Support mit ausschließlich Bug-Fixes befindet. Außerdem wird darauf hingewiesen, dass Mac nicht intensiv getestet wird und die Mac-Installation inoffiziell ist. Fooocus ist damit eine begrenzte Option für einen bestehenden Fooocus-Workflow, nicht jedoch der Standardweg für neue Architekturen oder ein macOS-Setup, das Sie langfristig warten möchten.

Führen Sie einen repräsentativen Abnahmetest durch

Verwenden Sie vor der Festlegung auf ein Tool einen kleinen Abnahmetest:

  1. Reproduzieren Sie ein Text-to-Image-Basisergebnis anhand eines dokumentierten Seeds und der aufgezeichneten Einstellungen.
  2. Führen Sie die anspruchsvollste erforderliche Operation aus: Inpainting, ControlNet, LoRA, Upscale oder einen mehrstufigen Graphen.
  3. Starten Sie die Anwendung neu und reproduzieren Sie den Workflow aus den gespeicherten Artefakten.
  4. Messen Sie Cold Start, Generierungszeit, maximale Memory Pressure und Output-Dimensionen.
  5. Übertragen Sie den Workflow auf ein sauberes Benutzerkonto oder einen anderen Rechner und erfassen Sie jede fehlende Dependency.
  6. Prüfen Sie die Bindung an das lokale Netzwerk, Downloads, Analytics-Einstellungen, Lizenzen und die Herkunft der Models.

Vergleichen Sie Tools nicht mit unterschiedlichen Checkpoints, Auflösungen, Step-Anzahlen oder Precision-Werten und bezeichnen Sie das Ergebnis anschließend als Runtime-Benchmark.

Eine praktische Standardempfehlung

Beginnen Sie bei explorativer Arbeit mit einer nativen App und einem von ihr dokumentierten Model. Wechseln Sie zu ComfyUI, sobald der Workflow selbst wertvoll wird: wenn er überprüft, wiederholt, automatisiert oder an jemand anderen übergeben werden muss. Behalten Sie AUTOMATIC1111 oder Fooocus bei, wenn eine bestehende Dependency deren spezifische Oberfläche nützlich macht.

Erhaltenswert ist das kleinste reproduzierbare Paket aus Model-Identitäten, Parametern, Dependencies und Workflow-Zustand, mit dem sich das Ergebnis erneut erzeugen lässt.

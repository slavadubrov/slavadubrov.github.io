MacBook-Setup für AI Engineering: macOS-Tools und Workflow

Viacheslav Dubrov

2025-04-19 · Aktualisiert 2026-08-16 · 5 Min. · Entwicklungswerkzeuge

Automatische Übersetzung Dieser Artikel wurde automatisch aus der englischen Originalversion übersetzt.

Das ist meine Checkliste, um eine frische macOS-Installation in eine AI-Engineering-Workstation zu verwandeln: Command-Line-Tools, Homebrew, Python, Docker, Terminal-Defaults und Editor-Setup.

TL;DR

Homebrew, Python mit uv, die mitgelieferte Zsh mit Oh My Zsh und Powerlevel10k, Docker, meine Editoren und lokale AI-Tools. Haltet die Befehle und Dotfiles unter Versionskontrolle, damit das Setup reproduzierbar bleibt.

1. Xcode Command Line Tools installieren

xcode-select --install

Dadurch wird ein Dialog geöffnet, der euch durch die Installation führt.

2. Homebrew installieren

Homebrew ist der Package Manager, den ich für alles Weitere auf dieser Liste verwende:

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

Der Installer erklärt, welche Änderungen vorgenommen werden, und bittet um Bestätigung. Auf Apple Silicon verwendet Homebrew standardmäßig /opt/homebrew. Führt den am Ende ausgegebenen brew shellenv-Befehl aus; Homebrew fügt brew nicht automatisch zu PATH eurer Shell hinzu.

3. Die grundlegenden Tools installieren

Byte says

Ich führte den Homebrew-Installer aus, gab brew install ein und erhielt command not found. Der Installer gibt die Zeile brew shellenv am Ende nicht ohne Grund aus.

brew install openssl readline sqlite3 xz zlib uv htop gitmoji pandoc ncdu tmux

Grob nach Verwendungszweck gruppiert:

Python-Umgebung

Bevor ich uv verwendet habe, habe ich pyenv zur Verwaltung meiner Python-Umgebungen genutzt. uv deckt diesen alltäglichen Workflow für mich inzwischen ab.

  • uv installiert Python-Versionen und verwaltet Projektumgebungen, Dependencies, Befehle und Lockfiles.
  • pyenv ist optional. Ich verwende es nur, wenn ich einen aus dem Quellcode gebauten Interpreter oder individuelle CPython-Build-Optionen benötige, die uv in seinen vorkompilierten Distributionen nicht anbietet.

Die neueste von uv verwaltete Python-Version installieren:

uv python install

Dieser Befehl installiert die neueste Python-Version, die uv zum Zeitpunkt des Setups verfügbar ist. Für eine projektspezifische Version verwendet den Pinning-Workflow im verlinkten uv-Guide.

pyenv separat installieren, wenn ihr diesen Source-Build-Weg benötigt:

brew install pyenv

Systembibliotheken

  • openssl stellt Unterstützung für SSL/TLS-Kryptografie bereit.
  • readline ergänzt die Textbearbeitung auf der Command Line.
  • sqlite3 ist eine leichtgewichtige eingebettete Datenbank.
  • xz und zlib stellen Datenkompression bereit.

Produktivitätstools

  • htop ist ein visueller System- und Prozessmonitor.
  • tmux verwaltet mehrere Terminal-Sessions.
  • ncdu analysiert den Festplattenverbrauch interaktiv.
  • gitmoji ergänzt Commit-Nachrichten um Emojis.
  • pandoc konvertiert Dokumente zwischen verschiedenen Formaten.

Mehr zu uv selbst findet ihr in meinem Quick Guide zur Verwaltung von Python auf macOS mit uv.

4. Ein Terminal auswählen

Das standardmäßige macOS-Terminal ist völlig ausreichend. Ich habe jahrelang iTerm2 verwendet und bin vor Kurzem zu Warp gewechselt, einem Rust-basierten Terminal mit integrierten AI-Features. Die Wahl ist persönlich; das spätere Setup hängt nicht davon ab.

Optional: iTerm2 einrichten

Wenn ihr bei iTerm2 bleibt, ändere ich immer diese beiden Einstellungen:

Natürliches Text-Editing aktivieren

  1. Preferences → Profiles → Keys → Key Mappings
  2. Klickt auf das Dropdown-Menü Presets…
  3. Wählt „Natural Text Editing“

Ein Farb-Theme auswählen

  1. Durchsucht die Themes unter iTerm2-Color-Schemes
  2. Preferences → Profiles → Colors → Color Presets…
  3. Klickt auf Import und wählt euer heruntergeladenes Theme aus

5. Zsh einrichten

macOS enthält Zsh bereits und verwendet sie als standardmäßige Login-Shell. Ich nutze die mitgelieferte /bin/zsh; installiert Homebrews Zsh nur, wenn ihr eine bestimmte neuere Upstream-Version benötigt.

Installierte Zsh und aktuelle Login-Shell prüfen:

echo "$SHELL"
command -v zsh
zsh --version

Wenn Zsh installiert, aber nicht als Login-Shell ausgewählt ist, wechselt zur mitgelieferten Version:

chsh -s /bin/zsh

Öffnet nach der Änderung der Login-Shell ein neues Terminal.

Oh My Zsh ergänzt darauf aufbauend die Defaults und das Plugin-System, die ich verwende. Der offizielle Installer lautet:

sh -c "$(curl -fsSL https://raw.githubusercontent.com/ohmyzsh/ohmyzsh/master/tools/install.sh)"

Das Projekt empfiehlt, einen unbekannten Installer vor der Ausführung zu überprüfen. Außerdem wird dokumentiert, dass ein vorhandenes .zshrc während der Installation in .zshrc.pre-oh-my-zsh umbenannt wird.

6. Zsh-Plugins hinzufügen

Installiert die beiden externen Plugins im benutzerdefinierten Plugin-Verzeichnis von Oh My Zsh:

git clone https://github.com/zsh-users/zsh-autosuggestions "${ZSH_CUSTOM:-$HOME/.oh-my-zsh/custom}/plugins/zsh-autosuggestions"
git clone https://github.com/zsh-users/zsh-syntax-highlighting.git "${ZSH_CUSTOM:-$HOME/.oh-my-zsh/custom}/plugins/zsh-syntax-highlighting"

Bearbeitet eure ~/.zshrc, um diese Plugins zu laden:

plugins=(
    aws bgnotify brew docker docker-compose
    emoji forklift gcloud git history iterm2
    keychain kubectl macos pre-commit
    pyenv pylint python screen themes
    tmux virtualenv vscode
    zsh-autosuggestions zsh-syntax-highlighting
)

Lasst zsh-syntax-highlighting in diesem Array an letzter Stelle.

Entfernt pyenv aus der Plugin-Liste, wenn ihr die optionale pyenv-Installation übersprungen habt.

Beschreibungen zu allen Plugins findet ihr im Oh My Zsh Plugins Wiki.

Die letzten beiden benötigen eine separate Installation:

  • zsh-autosuggestions schlägt beim Tippen Befehle aus eurer History vor.
  • zsh-syntax-highlighting färbt Befehle während der Eingabe ein, wodurch sich Tippfehler leichter erkennen lassen.

Befolgt die Installationsanweisungen in den jeweiligen Repositories.

7. Mit Powerlevel10k ein Theme festlegen

Powerlevel10k ist das Zsh-Theme, das ich verwende. Es zeigt das Arbeitsverzeichnis, den Git-Status und die aktive Python-Umgebung im Prompt an und bietet einen interaktiven Wizard zur Anpassung des Erscheinungsbilds. Die Installationsanweisungen findet ihr auf der GitHub-Seite.

Powerlevel10k-Font installieren

Wenn ihr VS Code mit einem integrierten Terminal verwendet, installiert den empfohlenen Font, bevor ihr die Terminal-Schriftart festlegt. Dadurch können die Powerlevel10k-Icons korrekt dargestellt werden. p10k configure kann den Font automatisch in iTerm2 installieren. Für andere Terminals ladet die vier TTF-Dateien aus dem Powerlevel10k Font Guide herunter und installiert sie.

Setzt in VS Code die Terminal-Schriftart auf MesloLGS NF:

  1. Öffnet die Einstellungen eures Editors
  2. Sucht nach terminal.integrated.fontFamily
  3. Setzt den Wert auf MesloLGS NF

Das vollständige Font-Setup findet ihr im Powerlevel10k Font Guide.

9. Der Rest

Ein paar Extras installiere ich auf jedem Rechner:

  • GitHub Desktop — visueller Git-Client, wenn ich nicht auf die CLI wechseln möchte
  • Docker Desktop — der Container-Runtime, die ich verwende; Podman Desktop ist eine Alternative
  • Ollama oder LM Studio — LLMs lokal auf dem Mac ausführen

10. Das Setup ist abgeschlossen

Alles oben Genannte kommt auf jedes neue MacBook, bevor ich mit der eigentlichen Arbeit beginne. Passt das Setup nach eurem Geschmack an.

Wichtigste Erkenntnisse

  1. Dies ist ein persönliches Setup, keine minimale oder universelle macOS-Baseline. Entfernt alles, was ihr nicht verwendet.
  2. Die mitgelieferte /bin/zsh reicht für dieses Setup aus. Installiert Homebrews Zsh nur, wenn ihr eine bestimmte neuere Upstream-Version benötigt.
  3. uv übernimmt in meinem alltäglichen Workflow inzwischen die Python-Installation und Projektumgebungen. pyenv bleibt für aus dem Quellcode gebaute oder individuell konfigurierte CPython-Interpreter optional.
  4. Dokumentiert Installationsbefehle, Dotfiles ohne Secrets, Editor-Extensions und Model-Speicherorte, damit das nächste Setup mechanisch reproduzierbar ist.

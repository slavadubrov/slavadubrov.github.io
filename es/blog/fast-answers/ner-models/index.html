Mejores modelos de NER: spaCy, GLiNER, Transformers y LLMs

El reconocimiento de entidades con nombre (NER) encuentra y etiqueta fragmentos de texto, como personas, empresas y códigos de producto. Los requisitos de producción dependen del caso de uso. Un pipeline de redacción puede detenerse en la detección de fragmentos, mientras que el entity linking necesita normalización a IDs estables. La validación, la latencia y los umbrales de revisión deben definirse a partir de la carga de trabajo.

Usa spaCy para obtener etiquetas estables y pipelines rápidos. Elige GLiNER cuando las etiquetas cambien con frecuencia, o ajusta mediante fine-tuning un clasificador de tokens basado en Transformer cuando dispongas de ejemplos etiquetados. Usa extracción estructurada basada en LLMs cuando necesites un registro complejo en lugar de una lista sencilla de fragmentos.

Cómo elegir

Empieza por el esquema de entidades, no por el modelo.

Si las etiquetas son estables y dispones de ejemplos representativos, ajusta mediante fine-tuning un clasificador de tokens y compáralo en un conjunto de dominio reservado para evaluación. Predice etiquetas de tokens sin generación autoregresiva, pero la latencia y el coste reales siguen dependiendo del modelo, el hardware, el tamaño del batch y el stack de serving.

Si las etiquetas cambian cada semana, usa GLiNER o un extractor basado en LLM mientras se estabiliza la ontología. El objetivo es entender cómo debe ser el esquema antes de invertir presupuesto en anotación.

Si la salida es un registro estructurado en lugar de fragmentos, usa un LLM con structured outputs o un pipeline híbrido. Muchas tareas de extracción empresarial no son NER puro. «Encuentra las partes, las obligaciones, la fecha de entrada en vigor, la cláusula de rescisión y la ley aplicable» es comprensión documental con campos de entidades.

Pipeline de producción

Un pipeline de extracción de producción suele añadir varias etapas alrededor del modelo:

  1. Extracción de candidatos: spaCy, GLiNER, un modelo Transformer, un LLM, reglas o una combinación de estos.
  2. Normalización o entity linking opcional: asignar los fragmentos a IDs canónicos, códigos de producto, usuarios, empresas o entradas de una ontología.
  3. Validación y revisión: rechazar etiquetas imposibles, aplicar restricciones del esquema, deduplicar fragmentos y enviar los casos dudosos a revisión.

La normalización convierte el texto extraído en datos de producto útiles. Encontrar el fragmento «Apple» es solo el primer paso. El sistema aún debe decidir si se refiere a la empresa, a la fruta, a una familia de productos o a un ticker bursátil, y después asignarlo a un ID estable.

Lista de comprobación para la evaluación

Mide algo más que el F1 a nivel de entidad:

  • exact span F1
  • relaxed span F1
  • matriz de confusión de etiquetas
  • gestión de entidades anidadas
  • precisión de la normalización de entidades
  • falsos positivos por etiqueta
  • calibración de confianza
  • latencia y coste por documento
  • tasa de correcciones humanas

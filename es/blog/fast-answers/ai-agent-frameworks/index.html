Mejores frameworks de agentes de AI: LangGraph, CrewAI y OpenAI SDK

Todos los frameworks de agentes proporcionan un agent loop que permite al modelo elegir y usar herramientas. La diferencia importante está en lo que cada framework gestiona alrededor de ese loop: estado, retrieval, handoffs, tracing o despliegue.

Opción predeterminada: LangGraph para disponer de un estado explícito y un flujo de control duradero. OpenAI Agents SDK para un runtime Python compacto y nativo de OpenAI. LlamaIndex cuando el retrieval es el producto. CrewAI solo cuando el trabajo encaja con roles y handoffs. Microsoft Agent Framework para sistemas con un uso intensivo de Microsoft o Azure. SmolAgents para agentes pequeños y code-first.

Cómo elegir

Empieza por el flujo de control: cómo pasa el agente de un paso a otro y cómo gestiona los fallos.

Si el agente tiene estados claros, reintentos, aprobaciones, checkpoints y ejecuciones reanudables, usa LangGraph. Escribirás más estructura al principio, pero esa estructura forma parte del sistema. LangGraph es la opción predeterminada adecuada cuando la ejecución puede durar más que una única petición HTTP o cuando necesitas explicar por qué el agente hizo algo.

Cuando el flujo de control esté claro, considera el encaje con la plataforma.

Si tu stack ya usa modelos de OpenAI y quieres una API de Python compacta, usa OpenAI Agents SDK. Tendrás agentes, herramientas, guardrails, sesiones y tracing en un único lugar. No pretende ser un motor de grafos genérico, y esa es precisamente una de sus ventajas.

A continuación, considera los datos con los que trabaja el agente.

Si tu agente trabaja principalmente con documentos, índices, retrieval y query engines, empieza con LlamaIndex. Normalmente es mejor que crear una capa de retrieval personalizada y añadirle después un framework de agentes. La mayoría de los agentes documentales fallan porque el retrieval y la evaluación estaban poco especificados, no porque el loop fuera demasiado sencillo.

Por último, usa roles solo cuando reflejen el workflow real.

CrewAI resulta útil cuando el proceso real tiene roles: investigador, analista, revisor, redactor y operador. Es menos convincente cuando inventas roles solo para utilizar una abstracción multi-agent. Los nombres no gestionan el estado.

Cuándo no usar un framework de agentes

No empieces con un framework de agentes cuando un workflow tipado, un endpoint de búsqueda o un motor de reglas resuelva el problema. Los agentes ayudan cuando el sistema necesita elegir el siguiente paso después de ver resultados intermedios. Encajan mal con ETL fijo, aprobaciones deterministas, flujos de facturación o cualquier caso en el que todas las ramas se conozcan de antemano.

No construyas un sistema multi-agent antes de que un único agente funcione bien. Dividir un workflow inestable entre varios agentes añade fallos de coordinación y latencia.

No confundas la observability del framework con la evaluación del producto. Los traces te dicen qué ha ocurrido. Las evals te dicen si el resultado ha sido bueno.

Mi ruta predeterminada

  1. Crea la primera versión como un único agente con herramientas limitadas.
  2. Añade traces y un dataset pequeño de regresión antes de añadir memory.
  3. Pasa a LangGraph cuando las transiciones de estado se conviertan en parte del producto.
  4. Usa OpenAI Agents SDK cuando el producto sea nativo de OpenAI y el loop deba mantenerse compacto.
  5. Añade agentes basados en roles solo cuando las responsabilidades sean realmente separables.

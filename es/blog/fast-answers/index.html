Agentes de AI

  • ¿Necesito un agente o un workflow fijo?

    Usa un workflow fijo cuando puedas definir los pasos y las bifurcaciones. Plantéate usar pasos elegidos por el modelo cuando las reglas fijas no permitan resolver la tarea de forma fiable.

  • ¿Con qué framework de agentes debería empezar?

    Elígelo según el control que necesites sobre los pasos, el progreso guardado y la recuperación. Compara un SDK pequeño con un workflow basado en grafos antes de añadir más componentes.

  • ¿Qué herramienta de evaluación de agentes debería usar?

    Empieza por el objetivo: inspeccionar ejecuciones, probar cambios o comprobar acciones de las herramientas. Una herramienta puede ayudarte a ejecutar tus tests; aun así, debes definir qué significa que una tarea se ha completado correctamente.

  • ¿Cómo debería proteger un agente de AI?

    Limita lo que pueden hacer sus herramientas. Comprueba los permisos antes de ejecutar acciones, aísla la ejecución de código y solicita aprobación cuando las consecuencias lo requieran.

  • ¿Debería usar function calling, MCP, una CLI o skills?

    Cumplen objetivos distintos y pueden combinarse. Decide por separado cómo exponer una herramienta y qué instrucciones explican cuándo utilizarla.

  • ¿Cuándo ayuda el razonamiento guiado por un schema?

    Úsalo cuando necesites comprobar campos intermedios antes de ejecutar una acción. Una estructura válida sigue necesitando comprobaciones de evidencias y reglas de aplicación.

Recuperación y documentos

  • ¿Qué modelo de NER se adapta a mis entidades?

    Empieza por tus etiquetas y ejemplos. Las etiquetas estables, las etiquetas cambiantes, los spans solapados y los hechos inferidos entre varias frases requieren tests distintos.

  • ¿Qué herramienta de OCR se adapta a mis documentos?

    Prueba el resultado que necesitas: texto, orden de lectura, tablas o campos concretos. Los escaneos limpios y las maquetaciones complejas pueden requerir enfoques distintos.

  • ¿Necesito RAG básico, agentic RAG o GraphRAG?

    Empieza con una única pasada de retrieval. Plantéate repetir la búsqueda cuando las preguntas posteriores dependan de resultados anteriores, o usar GraphRAG cuando necesites resúmenes de una colección.

  • ¿Qué herramientas y métricas de evaluación de RAG debería usar?

    Comprueba por separado las evidencias recuperadas y la respuesta generada. Elige las métricas según el fallo que necesites detectar y los datos de referencia disponibles.

  • ¿Cuándo debería añadir embeddings o un reranker?

    Mide primero una baseline de búsqueda por palabras clave. Añade otra etapa solo cuando solucione un problema medido de retrieval o ranking dentro de tu presupuesto de tiempo.

Modelos y herramientas locales

  • ¿Qué herramienta local para LLM debería usar en macOS?

    Elígela según cómo quieras trabajar: una interfaz de escritorio, una API local o código Python. Comprueba que el modelo seleccionado se ejecuta realmente en tu Mac.

  • ¿Qué formato de cuantización de LLM debería usar?

    Comprueba primero qué admiten tu runtime y tu hardware. Después compara el uso de memoria, la velocidad y la calidad en tu tarea.

  • ¿Debería usar prompting, RAG o fine-tuning?

    Prueba prompting para las instrucciones, retrieval para el conocimiento que falta y fine-tuning para comportamientos que puedas demostrar con ejemplos. Puede que necesites más de una opción.

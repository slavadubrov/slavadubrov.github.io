Tutorial de servidor MCP con uv y FastMCP: Construir un servidor FeatureStoreLite

Este tutorial de servidor MCP permite crear un pequeño servidor de almacén de características mediante FastMCP, ejecutarlo con uv e integrarlo en Claude Desktop.

Resumen rápido: Un servidor FastMCP sencillo es suficiente para ofrecer una herramienta local útil a un agente. Utilice uv para configuraciones reproducibles, mantenga los límites del servidor bien definidos, valide las entradas con esquemas tipados y pruebe la herramienta MCP antes de conectarla a un modelo.

¿Qué es un servidor MCP?

El Model Context Protocol (MCP) es un estándar abierto para conectar asistentes de IA con datos y herramientas externas. Sustituye la necesidad de integraciones personalizadas separadas para cada herramienta por un conjunto único de convenciones.

En este tutorial construiremos un servidor MCP FeatureStoreLite. Este se sitúa entre un LLM y un almacén de características (una base de datos con características de ML precomputadas) y ofrece herramientas para consultar y escribir vectores de características indexados por usuario, producto o documento.

¿Por qué crearlo?

Usted es ingeniero de ML que está depurando una pipeline. En lugar de recurrir a SQL o escribir un script rápido para comprobar valores de características, puede preguntar directamente a Claude: “¿Cuál es el vector de características del usuario_123?” o “Muéstreme los metadatos del producto_abc.” El servidor MCP hace posible esto.

¿Por qué utilizar uv?

Utilizaremos uv para instalar paquetes, resolver dependencias y gestionar el entorno virtual. Más adelante, uv run --with mcp[cli] ... también permitirá que la configuración de Claude Desktop declare sus dependencias directamente. Esto evita la existencia de un entorno separado que podría desincronizarse.

Visión general de la arquitectura

Las cuatro componentes y cómo se integran:

  1. El usuario formula una pregunta en lenguaje natural.
  2. Claude Desktop actúa como cliente MCP. Elige una herramienta según la pregunta y la llama.
  3. Nuestro servidor FastMCP expone get_feature y store_feature como herramientas MCP.
  4. SQLite sirve como almacenamiento subyacente para los vectores de características.

2. Configuración e instalación

Si aún no cuenta con uv, instálelo. El resto del tutorial parte de la premisa de que ya está disponible en su PATH.

2.2. Inicializar el proyecto

Cree un directorio nuevo e inicialice un proyecto Python. uv init generará automáticamente un pyproject.toml para usted.

3. Construcción del servidor

Dos archivos, organizados por funcionalidad:

  1. database.py se encarga de las operaciones con SQLite.
  2. featurestore_server.py define el servidor MCP.

3.1. Capa de base de datos (database.py)

Este módulo gestiona la conexión a SQLite y algunos auxiliares. Se inicializa con dos filas de ejemplo para que el servidor tenga algo que devolver en la primera consulta.

Cree database.py:

# database.py
import json
import os
import sqlite3


def get_db_path() -> str:
    """Get the database path - always in the script's directory"""
    script_dir = os.path.dirname(os.path.abspath(__file__))
    return os.path.join(script_dir, "features.db")


def init_db() -> None:
    """Initialize the feature store database with table and sample data"""
    conn = sqlite3.connect(get_db_path())
    conn.execute("""
        CREATE TABLE IF NOT EXISTS features (
            key TEXT PRIMARY KEY,
            vector TEXT NOT NULL,
            metadata TEXT,
            created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
        )
    """)

    # Sample data for experimentation
    example_features = [
        (
            "user_123",
            "[0.1, 0.2, -0.5, 0.8, 0.3, -0.1, 0.9, -0.4]",
            json.dumps({"type": "user", "id": 123, "segment": "premium"}),
        ),
        (
            "product_abc",
            "[0.7, -0.3, 0.4, 0.1, -0.8, 0.6, 0.2, -0.5]",
            json.dumps({"type": "product", "id": "abc", "category": "electronics"}),
        ),
    ]

    # Insert if not exists
    for key, vector, metadata in example_features:
        try:
            conn.execute(
                "INSERT INTO features (key, vector, metadata) VALUES (?, ?, ?)",
                (key, vector, metadata),
            )
        except sqlite3.IntegrityError:
            pass  # Already exists

    conn.commit()
    conn.close()


def get_db_connection() -> sqlite3.Connection:
    """Get a database connection"""
    return sqlite3.connect(get_db_path())


if __name__ == "__main__":
    init_db()
    print("✅ Database initialized successfully!")

Inicialice la base de datos:

uv run python database.py

3.2. El servidor MCP (featurestore_server.py)

FastMCP se encarga de la mayor parte del trabajo. Basta con decorar una función estándar de Python para que quede registrada como una herramienta o recurso MCP. La documentación generada sirve como descripción que verá el LLM, por lo que debe redactarse dirigida a estos modelos y no solo a personas.

Cree featurestore_server.py:

# featurestore_server.py
import json
from mcp.server.fastmcp import FastMCP
from database import get_db_connection, init_db

# Initialize the MCP Server
mcp = FastMCP("FeatureStoreLite")

# Ensure DB is ready when server starts
init_db()


@mcp.resource("schema://main")
def get_schema() -> str:
    """
    Resource: Provide the database schema.
    Resources are passive data that LLMs can read like files.
    """
    conn = get_db_connection()
    try:
        schema = conn.execute(
            "SELECT sql FROM sqlite_master WHERE type='table'"
        ).fetchall()
        return "\n".join(sql[0] for sql in schema if sql[0]) or "No tables found."
    finally:
        conn.close()


@mcp.tool()
def store_feature(key: str, vector: str, metadata: str | None = None) -> str:
    """
    Tool: Store a feature vector.
    Tools are executable functions that LLMs can call to perform actions.
    """
    conn = get_db_connection()
    try:
        # Validate that vector is valid JSON
        json.loads(vector)

        conn.execute(
            "INSERT OR REPLACE INTO features (key, vector, metadata) VALUES (?, ?, ?)",
            (key, vector, metadata),
        )
        conn.commit()
        return f"Successfully stored feature '{key}'"
    except json.JSONDecodeError:
        return "Error: Vector must be a valid JSON array string (e.g., '[0.1, 0.2]')"
    except Exception as e:
        return f"Error: {str(e)}"
    finally:
        conn.close()


@mcp.tool()
def get_feature(key: str) -> str:
    """
    Tool: Retrieve a feature vector by key.
    """
    conn = get_db_connection()
    try:
        row = conn.execute(
            "SELECT vector, metadata FROM features WHERE key = ?", (key,)
        ).fetchone()

        if row:
            return json.dumps(
                {
                    "key": key,
                    "vector": json.loads(row[0]),
                    "metadata": json.loads(row[1]) if row[1] else None,
                },
                indent=2,
            )
        return f"Feature '{key}' not found."
    finally:
        conn.close()


@mcp.tool()
def list_features() -> str:
    """
    Tool: List all available feature keys.
    """
    conn = get_db_connection()
    try:
        rows = conn.execute("SELECT key FROM features").fetchall()
        return json.dumps([row[0] for row in rows])
    finally:
        conn.close()


if __name__ == "__main__":
    mcp.run()

4. Pruebas con MCP Inspector

Antes de integrarlo en Claude, verifique el funcionamiento del servidor mediante el MCP Inspector. Se trata de una pequeña interfaz web que permite llamar a herramientas y leer recursos directamente.

uv run mcp dev featurestore_server.py

Este comando inicia el servidor y abre la interfaz del Inspector en su navegador (generalmente en http://localhost:5173).

{width=“600”}

Llame a get_feature pasando como parámetro key="user_123". Si se devuelve el JSON correspondiente a la fila de semilla, significa que el servidor funciona correctamente.

5. Conexión con Claude Desktop

Una vez que el Inspector confirme que el servidor funciona, regístrelo en Claude Desktop.

5.1. Configurar Claude

Edite el archivo de configuración de Claude Desktop:

  • macOS: ~/Library/Application Support/Claude/claude_desktop_config.json
  • Windows: %APPDATA%/Claude/claude_desktop_config.json

Añada su servidor al objeto mcpServers:

{
    "mcpServers": {
        "featurestore": {
            "command": "uv",
            "args": [
                "run",
                "--with",
                "mcp[cli]",
                "mcp",
                "run",
                "/ABSOLUTE/PATH/TO/mcp-featurestore/featurestore_server.py"
            ]
        }
    }
}

Importante: la ruta hacia featurestore_server.py debe ser absoluta. Una ruta relativa provocará un fallo silencioso, ya que Claude Desktop se ejecuta desde un directorio de trabajo distinto.

5.2. Cómo funciona la interacción

A continuación se describe el flujo completo cuando Claude necesita buscar una característica:

  1. Claude identifica las herramientas disponibles (get_feature, list_features, etc.).
  2. Determina que la consulta requiere datos del almacén de características.
  3. Construye una llamada a herramienta y la envía a su servidor.
  4. El servidor ejecuta la función de Python y devuelve el resultado.
  5. Claude utiliza dicho resultado para generar la respuesta final.

5.3. Ejemplos de consultas

Reinicie Claude Desktop e intente algunas solicitudes:

  1. “Liste todas las características disponibles.” {width=“600”}

  2. “Obtenga el vector de características de user_123.” {width=“600”}

6. Solución de problemas

Algunos casos de fallo que conviene conocer:

  • “Error en la conexión al servidor”:

    • Consulte los registros en ~/Library/Logs/Claude/mcp.log en macOS.
    • Asegúrese de que la configuración utilice una ruta absoluta y no relativa.
    • Verifique que uv se encuentre en PATH de Claude Desktop. De no ser así, indique la ruta binaria completa; which uv le indicará dónde se encuentra.

  • “Error al ejecutar la herramienta”:

    • Reproduzca el problema en el Inspector utilizando uv run mcp dev featurestore_server.py. La interfaz muestra el error original, que Claude Desktop suele ocultar.
    • Compruebe que features.db se genere junto a database.py. Si el directorio de trabajo cambia, es la ruta relativa al script en get_db_path() la que permite evitar problemas.

7. Conclusión

Eso es todo: un servidor FastMCP, un almacén de datos basado en SQLite y una configuración de Claude Desktop que apunta a un comando uv run. Esta misma estructura sirve para cualquier componente que pueda encapsularse en una función de Python. Basta sustituir las llamadas a SQLite por un verdadero almacén de características, una API interna o un registro de modelos para que el tamaño del servidor siga siendo reducido.

Puntos clave

  1. MCP constituye un límite entre herramientas, no una justificación para exponer todas las funciones internas.
  2. Mantener las herramientas del servidor pequeñas, tipadas y fáciles de probar sin necesidad de un LLM.
  3. Utilizar uv para poder reconstruir el entorno del tutorial desde cero.
  4. Tratar al servidor MCP como código de producción una vez que un agente pueda llamarlo.

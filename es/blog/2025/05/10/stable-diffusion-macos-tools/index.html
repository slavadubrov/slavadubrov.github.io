Stable Diffusion en macOS: Draw Things, DiffusionBee, ComfyUI, A1111 y Fooocus

Ejecutar modelos de imágenes localmente en macOS es, en su mayor parte, una cuestión de elección de herramientas. Draw Things, DiffusionBee, ComfyUI, AUTOMATIC1111 y Fooocus tienen funciones similares, pero difieren en cuanto a configuración, soporte de modelos, control del flujo de trabajo, extensiones y capacidad de automatización.

Una aplicación de arrastrar y soltar permite comenzar rápidamente; en cambio, un grafo de nodos requiere más tiempo para aprenderse, pero ofrece un acceso más profundo al proceso completo. En Apple Silicon, la aplicación, la familia de modelos, la precisión, el tamaño de la imagen y el flujo de trabajo influyen directamente en si la generación es posible. Elija la interfaz según el tipo de tarea que deba realizar y, a continuación, pruebe el modelo y las configuraciones específicas.

En resumen: Utilice Draw Things o DiffusionBee cuando una aplicación nativa ya cumple con la función necesaria. Opte por ComfyUI cuando sea necesario inspeccionar, compartir o automatizar el propio grafo de nodos. Elija AUTOMATIC1111 únicamente si su flujo de trabajo depende de su interfaz o extensiones. Considere Fooocus como una solución propia de la era de SDXL, ya que no ofrece soporte para los modelos actuales; su proyecto oficial cuenta con un soporte a largo plazo limitado.

Un archivo de modelo no equivale a un flujo de trabajo portátil

Varias aplicaciones pueden cargar archivos .safetensors, pero la existencia de una extensión compatible no garantiza compatibilidad total. Un pipeline completo también puede requerir una arquitectura específica, un codificador de texto, un VAE, un programador de tareas, ControlNet, LoRA, un tokenizador o configuraciones propias de la aplicación.

Debe registrarse la unidad de lanzamiento que generó la imagen:

  • la aplicación y su versión;
  • el repositorio del modelo, su revisión y licencia;
  • cada componente y adaptador del modelo;
  • el prompt, el prompt negativo, la semilla, el muestreador, el número de pasos, los parámetros de guía y las dimensiones;
  • el archivo del grafo o flujo de trabajo, si la aplicación lo proporciona.

Este registro es más importante que la popularidad de la aplicación. Incluso con la misma semilla, se pueden obtener resultados diferentes tras cambios en el backend, el modelo, el muestreador o la precisión.

La memoria unificada es compartida, no ilimitada

Apple Silicon permite que el CPU y la GPU accedan al mismo conjunto de memoria. Esto elimina las barreras entre copias independientes, pero macOS y todas las aplicaciones abiertas compiten por esa misma capacidad.

En la generación de imágenes, el uso máximo incluye elementos además de los pesos de los checkpoints:

peak memory ≈ model components
            + intermediate activations
            + attention and runtime workspace
            + loaded adapters and control models
            + application and OS memory

La resolución, el tamaño del lote, la arquitectura del modelo, la precisión, el escalado, ControlNet y el hecho de si los componentes siguen cargados afectan directamente al resultado. No compre ni elija una máquina basándose únicamente en tablas genéricas que indican “8/16/32 GB”. Pruebe el flujo de trabajo deseado y supervise la presión de memoria. Una generación que solo es posible gracias al uso continuo del intercambio de memoria no constituye un punto operativo estable.

Draw Things: interacción nativa y scripting

Draw Things es una aplicación para la plataforma Apple destinada a la generación local de imágenes. Su documentación actual aborda modelos, LoRAs, ControlNet, inversión textual, Core ML y scripting en JavaScript con versionado.

Elija esta opción cuando el trabajo debe permanecer dentro de una aplicación nativa pero se requiere un control mayor que el que ofrece un cuadro de prompts. Antes de estandarizarla, importe los componentes del modelo exactos y reproduzca una edición, adaptador o flujo de control representativo. “Nativo” se refiere a la interfaz e implementación; no garantiza compatibilidad ni velocidad para cada nueva arquitectura.

DiffusionBee: flujo de trabajo empaquetado para macOS

DiffusionBee agrupa la descarga de modelos y tareas comunes de generación en una aplicación de escritorio. Su documentación de proyecto enumera funciones como conversión imagen-a-imagen, relleno, expansión, ControlNet, LoRA, SDXL y soporte parcial para Flux.

Elija esta opción cuando la instalación y una UI integrada son más importantes que exportar un grafo de pipeline. Verifique la última versión y la arquitectura exacta antes de descargar un modelo grande: una etiqueta como “soporte para Flux” no implica que todos sus derivados, versiones cuantizadas o componentes auxiliares se cargarán.

ComfyUI: el flujo de trabajo es un artefacto

ComfyUI representa la generación mediante un grafo de nodos. Un flujo de trabajo puede almacenarse como archivo JSON independientemente de su salida, lo que permite inspeccionar y versionar el pipeline. Su ejecutor también puede evitar volver a calcular secciones del grafo cuyas entradas no han cambiado.

La versión actual de ComfyUI Desktop es compatible con Apple Silicon y gestiona su propio entorno, aunque la documentación oficial para macOS sigue etiquetándola como beta. También existe una versión instalable mediante Homebrew:

brew install comfyui

Elige ComfyUI cuando un pipeline cuente con ramas, componentes reutilizables, múltiples modelos o necesite automatización. Debes mantener unidos el archivo JSON, la versión de la aplicación, las versiones de los nodos core, las revisiones de los nodos personalizados y el manifiesto del modelo.

Los nodos personalizados son dependencias ejecutables, no simples presets inofensivos. Es necesario revisar su código fuente, instalar los scripts correspondientes, fijar las revisiones y aislar el entorno. Un grafo creado por un autor desconocido puede hacer referencia a códigos y modelos que aún no has auditado.

AUTOMATIC1111: compatibilidad con una UI web establecida

AUTOMATIC1111 Stable Diffusion WebUI ofrece parámetros de generación a través de una interfaz de navegador y admite scripts, extensiones y una API. Úsalo cuando algún tutorial, proceso automatizado o extensión existente forme parte de los requisitos.

Su guía oficial para Apple Silicon detalla las excepciones y limitaciones de rendimiento, incluyendo un bajo rendimiento en el entrenamiento. Asegúrate de que la funcionalidad necesaria funcione en las versiones específicas de macOS y PyTorch antes de adoptar una configuración basada en muchas extensiones.

Las extensiones ejecutan código dentro del entorno de la aplicación. Fíjalas, revisa sus actualizaciones y mantén el servicio en modo loopback, a menos que el acceso remoto sea intencional y esté protegido.

Fooocus: una opción limitada de la era SDXL

Fooocus oculta deliberadamente muchas decisiones técnicas detrás de un flujo de trabajo centrado exclusivamente en los prompts. Esto puede ser útil cuando sus valores predeterminados se ajustan a la tarea.

La README actual del proyecto indica que Fooocus está basado en SDXL y cuenta solo con soporte a largo plazo limitado, limitado a la corrección de errores. También señala que no se ha probado exhaustivamente en Mac y describe su instalación allí como no oficial. Por ello, Fooocus es una opción restringida para quienes ya utilizan su flujo de trabajo, y no representa la vía por defecto para nuevas arquitecturas o infraestructuras de macOS de larga duración.

Ejecuta una prueba de aceptación representativa

Antes de decidirte por una herramienta, utiliza un conjunto pequeño de pruebas de aceptación:

  1. Reproduce un resultado básico de texto a imagen a partir de una semilla y configuraciones registradas.
  2. Ejecuta la operación más compleja requerida: relleno de áreas, ControlNet, LoRA, ampliación o un grafo de varias etapas.
  3. Reinicia la aplicación y reproduce el flujo de trabajo a partir de los archivos guardados.
  4. Mide el tiempo de arranque, el tiempo de generación, la presión máxima de memoria y las dimensiones del resultado.
  5. Transfiere el flujo de trabajo a una cuenta o máquina limpia e identifica todas las dependencias faltantes.
  6. Verifica la vinculación a la red local, las descargas, la configuración de análisis, las licencias y el origen del modelo.

No compares herramientas que utilicen puntos de control, resoluciones, cantidades de pasos o niveles de precisión diferentes y llames al resultado un benchmark de rendimiento.

Una opción por defecto práctica

Para trabajos exploratorios, comienza con una aplicación nativa y un modelo que venga documentado con ella. Pasa a ComfyUI cuando el propio flujo de trabajo adquiera valor: cuando sea necesario revisarlo, repetirlo, automatizarlo o entregárselo a otra persona. Mantén AUTOMATIC1111 o Fooocus cuando alguna dependencia existente haga que su interfaz sea útil en tu caso concreto.

El activo duradero no es la captura de pantalla de un buen resultado, sino el paquete más reducido y reproducible que contenga las identidades del modelo, sus parámetros, dependencias y el estado del flujo de trabajo, y que permita obtener ese mismo resultado nuevamente.
